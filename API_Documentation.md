# API Documentation

**Base URL:** `http://localhost:8080`

---

## Общие сведения

Все методы принимают параметры POST-запросов в формате `application/x-www-form-urlencoded`, GET-параметры — через query string.

Сессия ведётся через cookie `PHPSESSID`. После успешной регистрации или входа сервер устанавливает cookie, которую необходимо передавать в последующих запросах.

Время жизни сессии — 30 дней с момента последнего запроса: каждый метод, требующий авторизации, продлевает сессию и переотправляет cookie с новым сроком действия. Клиент должен сохранять обновлённую cookie из ответа.

### Формат ответа

Успешный ответ:
```json
{ "status": 1, "response": { ... }, "actions": [ ... ] }
```

Поле `actions` опционально: оно есть только у успешных ответов и только если сервер передаёт клиенту дополнительные указания (см. [Actions](#actions)). Если actions нет, поле в ответе отсутствует.

Ответ с ошибкой:
```json
{ "status": 0, "errorCode": <int> }
```

При внутренней ошибке сервера ответ приходит с HTTP-статусом 500 и `errorCode` 9001.

### Actions

Action — указание клиенту, которое приходит в массиве `actions` успешного ответа вместе с основными данными. Все actions имеют одну структуру:

| Поле   | Тип    | Описание                                 |
|--------|--------|------------------------------------------|
| `type` | String | Тип action                               |
| `data` | Object | Данные action; формат зависит от `type`  |

Клиент должен игнорировать actions неизвестных ему типов.

#### Action `users`

Пользователи, фигурирующие в ответе на текущий запрос (участники переписки, отправители сообщений и т. п.). Получив этот action, клиент проверяет наличие пользователей в своём локальном кэше и недостающих (или устаревших) запрашивает методом [`/users/getBatch`](#get-usersgetbatch--пользователи-по-списку-id). Число id в action не ограничено, а `/users/getBatch` принимает не больше 100 за запрос — если нужно больше, клиент дозапрашивает пачками по 100.

| Поле `data` | Тип   | Описание                                         |
|-------------|-------|--------------------------------------------------|
| `userIds`   | Int[] | Идентификаторы пользователей, без повторов, по возрастанию |

```json
{
  "type": "users",
  "data": {
    "userIds": [1, 2]
  }
}
```

Если в ответе нет ни одного пользователя (например, пустой список сообщений), action не отдаётся.

Методы, отдающие action `users`:

| Метод                          | Какие пользователи                                     |
|--------------------------------|--------------------------------------------------------|
| `/conversations/createSingle`  | Участники переписки (`memberIds`)                      |
| `/conversations/getList`       | Участники всех переписок в выдаче (`memberIds`)        |
| `/messages/getList`            | Отправители сообщений в выдаче (`senderId`)            |
| `/messages/getBlock`           | Отправители сообщений блока (`senderId`)               |
| `/messages/send`               | Отправитель сообщения (`senderId`)                     |
| `/messages/edit`               | Отправитель сообщения (`senderId`)                     |

| Поле      | Тип           | Описание                                              |
|-----------|---------------|-------------------------------------------------------|
| `userId` | Int           | Идентификатор пользователя                            |
| `login`   | String        | Логин                                                 |
| `name`    | String        | Отображаемое имя                                      |
| `avatar`  | File \| null  | Аватар — объект [File](#объект-file) типа `image` (опционально) |

```json
{
  "userId": 1,
  "login": "ivan",
  "name": "Ivan Petrov",
  "avatar": {
    "fileId": 1,
    "type": "image",
    "url": "http://localhost:8080/static/uploads/2026/09/952c7adde9fc838c66ee905324c1e8fa.jpg",
    "size": 8293,
    "filename": "avatar.jpg",
    "extension": "jpg",
    "data": {
      "smallUrl": "http://localhost:8080/static/uploads/2026/09/952c7adde9fc838c66ee905324c1e8fa_small.jpg"
    }
  }
}
```

### Объект File

| Поле        | Тип    | Описание                                                        |
|-------------|--------|-----------------------------------------------------------------|
| `fileId`   | Int    | Идентификатор файла                                             |
| `type`      | String | Тип файла: `image` или `other` (список будет расширяться)        |
| `url`       | String | Ссылка на файл                                                  |
| `size`      | Int    | Размер в байтах                                                 |
| `filename`  | String | Имя файла                                                       |

| `data`      | Object | Дополнительная информация, состав зависит от `type` (см. ниже)   |

`data` для `other` — пустой объект `{}`.

`data` для `image`:

| Поле        | Тип    | Описание                                                                        |
|-------------|--------|---------------------------------------------------------------------------------|
| `smallUrl` | String | Ссылка на уменьшенную копию: не более 200 пикселей по меньшей стороне           |

```json
{
  "fileId": 1,
  "type": "image",
  "url": "http://localhost:8080/static/uploads/2026/09/952c7adde9fc838c66ee905324c1e8fa.jpg",
  "size": 8293,
  "filename": "photo.jpg",
  "extension": "jpg",
  "data": {
    "smallUrl": "http://localhost:8080/static/uploads/2026/09/952c7adde9fc838c66ee905324c1e8fa_small.jpg"
  }
}
```

### Объект Conversation

| Поле             | Тип          | Описание                                                                 |
|------------------|--------------|--------------------------------------------------------------------------|
| `conversationId` | Int          | Идентификатор переписки                                                  |
| `type`           | String       | Тип переписки: `single` (личная) или `group` (групповая)                 |
| `memberIds`      | Int[]        | Идентификаторы пользователей, состоящих в переписке (по возрастанию)     |
| `name`           | String \| null | Название — только для `group`; для `single` всегда `null`             |
| `avatar`         | File \| null   | Аватар — объект [File](#объект-file) типа `image`; только для `group`, опционально; для `single` всегда `null` |
| `opponentUserId` | Int \| null   | Идентификатор собеседника — только для `single` (второй участник относительно текущего пользователя); для `group` всегда `null`. Сам пользователь запрашивается через [`/users/getBatch`](#get-usersgetbatch--пользователи-по-списку-id) по [action `users`](#action-users) |
| `updatedAt`      | Int          | Время последнего изменения полей переписки (состав участников, название, аватар) — Unix timestamp в секундах. Новые сообщения его не меняют. Сейчас поля переписки после создания не меняются, поэтому равно времени создания |

```json
{
  "conversationId": 1,
  "type": "single",
  "memberIds": [1, 2],
  "name": null,
  "avatar": null,
  "opponentUserId": 2,
  "updatedAt": 1790846400
}
```

### Объект Message

| Поле             | Тип    | Описание                                                              |
|------------------|--------|-----------------------------------------------------------------------|
| `messageId`      | Int    | Идентификатор сообщения                                               |
| `clientId`       | String | Идентификатор, сгенерированный клиентом при отправке (см. [`/messages/send`](#post-messagessend--отправка-сообщения)); уникален в пределах отправителя. У сообщений, отправленных до появления поля, и у сообщений из админки — UUID, сгенерированный сервером |
| `conversationId` | Int    | Идентификатор переписки                                               |
| `blockId`        | Int    | Идентификатор блока, в котором лежит сообщение (см. [блоки сообщений](#блоки-сообщений)) |
| `senderId`       | Int    | Идентификатор пользователя, отправившего сообщение                    |
| `type`           | String | Тип сообщения: пока только `text`                                      |
| `text`           | String | Текст сообщения                                                       |
| `isEdited`       | Bool   | Было ли сообщение отредактировано                                     |
| `createdAt`      | Int    | Время создания — Unix timestamp в секундах                            |
| `updatedAt`      | Int    | Время последнего изменения — Unix timestamp в секундах; у неотредактированного сообщения равно `createdAt` |

```json
{
  "messageId": 15,
  "clientId": "6f1c2a9e-4b7d-4e3a-9c51-0d2f8b6a7e14",
  "conversationId": 1,
  "blockId": 2,
  "senderId": 1,
  "type": "text",
  "text": "Привет!",
  "isEdited": false,
  "createdAt": 1790846400,
  "updatedAt": 1790846400
}
```

### Блоки сообщений

Сообщения переписки хранятся блоками по 20 штук в порядке отправки: новое сообщение попадает в последний блок переписки, а если он заполнен — в новый. Идентификаторы блоков одной переписки возрастают от старых к новым. Блоки не пустые; заполненным может быть не только последний блок.

### Объект WebsocketConnectInfo

Данные для подключения к [WebSocket](#websocket). Отдаётся методами [`/global/start`](#get-globalstart--старт-работы-приложения) и [`/global/getWebsocketToken`](#get-globalgetwebsockettoken--токен-подключения-к-websocket).

| Поле        | Тип    | Описание                                                                                              |
|-------------|--------|-------------------------------------------------------------------------------------------------------|
| `url`       | String | Адрес WebSocket-сервера (`ws://` или `wss://`). Клиент не должен хранить его между вызовами — адрес может меняться |
| `token`     | String | Токен подключения: одноразовый (гасится при первой попытке авторизации соединения, даже неуспешной), привязан к текущему пользователю и текущей сессии |
| `expiresIn` | Int    | Сколько секунд токен действителен с момента выдачи (сейчас 120). Отсчитывается от получения ответа по монотонным часам, а не по системному времени устройства. Окончательный признак негодного токена — ошибка `2004` при подключении |

```json
{
  "url": "wss://example.com/ws",
  "token": "3f9c1e0b8a7d4c2e9f6a5b4c3d2e1f0a3f9c1e0b8a7d4c2e9f6a5b4c3d2e1f0a",
  "expiresIn": 120
}
```

### Коды ошибок

| Код  | Описание                                              | Методы                        |
|------|-------------------------------------------------------|-------------------------------|
| 1001 | Невалидный `login` (в т. ч. длиннее 64 символов)      | `/auth/signup`, `/auth/login` |
| 1002 | Пароль не соответствует требованиям                   | `/auth/signup`, `/auth/login` |
| 1003 | Невалидное `name` (в т. ч. длиннее 128 символов)      | `/auth/signup`                |
| 1004 | Невалидные параметры запроса                          | `/users/getList`, `/users/getBatch`, `/conversations/getList`, WS `auth` / `connect` |
| 1005 | Невалидный текст сообщения: пустой (после обрезки пробелов) или длиннее 4096 символов | `/messages/send`, `/messages/edit` |
| 1006 | Невалидный `clientId`: не передан, пустой, длиннее 64 символов или содержит символы кроме `A–Z`, `a–z`, `0–9`, `-`, `_` | `/messages/send` |
| 2001 | Логин уже занят                                       | `/auth/signup`                |
| 2002 | Неверный логин или пароль                             | `/auth/login`                 |
| 2003 | Пользователь не авторизован                           | `/auth/logout`, `/profile/get`, `/profile/setAvatar`, `/profile/removeAvatar`, `/files/uploadImage`, `/users/getList`, `/users/getBatch`, `/conversations/createSingle`, `/conversations/getList`, `/messages/getList`, `/messages/getBlock`, `/messages/send`, `/messages/edit`, `/global/getWebsocketToken` |
| 2004 | Токен подключения к WebSocket не найден, истёк, уже использован или выдан другому пользователю | WS `auth` / `connect` |
| 3001 | Файл не передан                                       | `/files/uploadImage`          |
| 3002 | Файл слишком большой (максимум 10 МБ или 25 мегапикселей) | `/files/uploadImage`      |
| 3003 | Файл не является изображением                         | `/files/uploadImage`, `/profile/setAvatar` |
| 3004 | Файл не найден / невалидный `fileId`                 | `/files/get`, `/profile/setAvatar` |
| 3005 | Ошибка сохранения файла                               | `/files/uploadImage`          |
| 4001 | Пользователь не найден / невалидный `userId`          | `/conversations/createSingle` |
| 5001 | Нельзя создать личную переписку с самим собой         | `/conversations/createSingle` |
| 5002 | Переписка не найдена, невалидный `conversationId` или пользователь в ней не состоит | `/messages/getList`, `/messages/send` |
| 6001 | Сообщение не найдено, невалидный `messageId` или сообщение из переписки, в которой пользователь не состоит | `/messages/edit` |
| 6002 | Блок сообщений не найден, невалидный `blockId` или блок из другой переписки | `/messages/getList`, `/messages/getBlock` |
| 6003 | Нельзя редактировать чужое сообщение                  | `/messages/edit`              |
| 6004 | `clientId` уже использован для сообщения текущего пользователя в другой переписке | `/messages/send` |
| 9001 | Внутренняя ошибка сервера                             | Все методы, WS `auth` / `connect` |

## Методы

### GET /global/start — Старт работы приложения

Возвращает данные, нужные клиенту для начала работы. Клиент вызывает метод:

- при запуске приложения;
- после входа, регистрации и выхода;
- при возврате приложения из фона.

Для переподключений к WebSocket используется лёгкий метод [`/global/getWebsocketToken`](#get-globalgetwebsockettoken--токен-подключения-к-websocket) — `/global/start` для этого не вызывается.

Метод доступен без авторизации. Для авторизованного пользователя продлевает сессию, как и остальные методы. Ответ отдаётся с заголовком `Cache-Control: no-store` (содержит токен). Состав ответа в дальнейшем будет расширяться — клиент должен игнорировать неизвестные поля.

#### Параметры запроса

Отсутствуют.

#### Успешный ответ

| Поле                    | Тип                           | Описание                                                                 |
|-------------------------|-------------------------------|--------------------------------------------------------------------------|
| `websocketConnectInfo`  | WebsocketConnectInfo \| null  | Объект [WebsocketConnectInfo](#объект-websocketconnectinfo); `null`, если пользователь не авторизован |

Авторизованный пользователь:
```json
{
  "status": 1,
  "response": {
    "websocketConnectInfo": {
      "url": "wss://example.com/ws",
      "token": "3f9c1e0b8a7d4c2e9f6a5b4c3d2e1f0a3f9c1e0b8a7d4c2e9f6a5b4c3d2e1f0a",
      "expiresIn": 120
    }
  }
}
```

Неавторизованный пользователь:
```json
{
  "status": 1,
  "response": {
    "websocketConnectInfo": null
  }
}
```

#### Ошибки

Специфичных ошибок нет: неавторизованный пользователь получает успешный ответ с `websocketConnectInfo: null`.

### GET /global/getWebsocketToken — Токен подключения к WebSocket

Выдаёт новый токен для (пере)подключения к [WebSocket](#websocket). Метод лёгкий — только выдаёт токен, и предназначен для частых вызовов при переподключениях. Требует активной сессии и продлевает её. Ответ отдаётся с заголовком `Cache-Control: no-store`.

#### Параметры запроса

Отсутствуют.

#### Успешный ответ

| Поле                   | Тип                  | Описание                                                       |
|------------------------|----------------------|----------------------------------------------------------------|
| `websocketConnectInfo` | WebsocketConnectInfo | Объект [WebsocketConnectInfo](#объект-websocketconnectinfo)     |

```json
{
  "status": 1,
  "response": {
    "websocketConnectInfo": {
      "url": "wss://example.com/ws",
      "token": "3f9c1e0b8a7d4c2e9f6a5b4c3d2e1f0a3f9c1e0b8a7d4c2e9f6a5b4c3d2e1f0a",
      "expiresIn": 120
    }
  }
}
```

#### Ошибки

| Код  | Описание                                                                                     |
|------|----------------------------------------------------------------------------------------------|
| 2003 | Пользователь не авторизован — клиент переходит в неавторизованное состояние и не переподключается |

### POST /auth/signup — Регистрация

Создаёт нового пользователя и устанавливает сессию.

#### Параметры запроса

| Поле       | Тип    | Обязательное | Требования                                                                                         |
|------------|--------|--------------|----------------------------------------------------------------------------------------------------|
| `login`    | String | Да           | Латинские буквы (a–z, A–Z), цифры, символ `_`; не длиннее 64 символов                             |
| `password` | String | Да           | Не менее 8 символов; минимум одна заглавная буква (A–Z), одна строчная (a–z), одна цифра (0–9)    |
| `name`     | String | Да           | Буквы (любые), цифры, дефис `-`, нижнее подчёркивание `_`, пробел; не длиннее 128 символов        |

#### Успешный ответ

В `response` — объект [User](#объект-user) созданного пользователя.

```json
{
  "status": 1,
  "response": {
    "userId": 1,
    "login": "ivan",
    "name": "Ivan Petrov",
    "avatar": null
  }
}
```

Выполняет вход для существующего пользователя и устанавливает сессию.

#### Параметры запроса

| Поле       | Тип    | Обязательное | Требования                                     |
|------------|--------|--------------|------------------------------------------------|
| `login`    | String | Да           | Латинские буквы (a–z, A–Z), цифры, символ `_` |
| `password` | String | Да           | Минимум 6 символов                             |

#### Успешный ответ

В `response` — объект [User](#объект-user) вошедшего пользователя.

```json
{
  "status": 1,
  "response": {
    "userId": 1,
    "login": "ivan",
    "name": "Ivan Petrov",
    "avatar": null
  }
}
```

### POST /profile/setAvatar — Установка аватара

Устанавливает аватар текущего пользователя. Требует активной сессии. Файл должен быть загружен этим же пользователем через `/files/uploadImage` и иметь тип `image`.

#### Параметры запроса

| Поле      | Тип | Обязательное | Описание                                   |
|-----------|-----|--------------|--------------------------------------------|
| `fileId` | Int | Да           | Идентификатор ранее загруженного изображения |

#### Успешный ответ

В `response` — обновлённый объект [User](#объект-user).

```json
{
  "status": 1,
  "response": {
    "userId": 1,
    "login": "ivan",
    "name": "Ivan Petrov",
    "avatar": {
      "fileId": 1,
      "type": "image",
      "url": "http://localhost:8080/static/uploads/2026/09/952c7adde9fc838c66ee905324c1e8fa.jpg",
      "size": 8293,
      "filename": "avatar.jpg",
      "extension": "jpg",
      "data": {
        "smallUrl": "http://localhost:8080/static/uploads/2026/09/952c7adde9fc838c66ee905324c1e8fa_small.jpg"
      }
    }
  }
}
```

#### Ошибки

| Код  | Описание                                                        |
|------|-----------------------------------------------------------------|
| 2003 | Пользователь не авторизован                                     |
| 3003 | Файл не является изображением                                   |
| 3004 | Файл не найден, невалидный `fileId` или файл принадлежит другому пользователю |

### POST /profile/removeAvatar — Удаление аватара

Убирает аватар текущего пользователя. Требует активной сессии. Сам файл не удаляется. Если аватар не был установлен — метод всё равно завершается успешно.

#### Параметры запроса

Отсутствуют.

#### Успешный ответ

В `response` — обновлённый объект [User](#объект-user) с `avatar: null`.

```json
{
  "status": 1,
  "response": {
```

### POST /messages/send — Отправка сообщения

Отправляет текстовое сообщение в переписку от лица текущего пользователя. Требует активной сессии; пользователь должен состоять в переписке.

Запрос идемпотентен по `clientId`: если у текущего пользователя уже есть сообщение с таким `clientId` в этой переписке, новое не создаётся — возвращается существующее (как есть, даже если `text` в повторе другой), WebSocket-событие повторно не рассылается. Поэтому при обрыве связи или таймауте клиент повторяет запрос с тем же `clientId`, не рискуя продублировать сообщение.

#### Параметры запроса

| Поле             | Тип    | Обязательное | Описание                                                                         |
|------------------|--------|--------------|----------------------------------------------------------------------------------|
| `conversationId` | Int    | Да           | Идентификатор переписки                                                          |
| `text`           | String | Да           | Текст сообщения. Пробелы по краям обрезаются (включая юникодные пробелы и невидимые символы: NBSP, zero-width space/joiner, BOM); после обрезки — от 1 до 4096 символов. Невалидные UTF-8 байты заменяются |
| `clientId`       | String | Да           | Идентификатор сообщения, сгенерированный клиентом до отправки — рекомендуется UUID v4. От 1 до 64 символов `A–Z`, `a–z`, `0–9`, `-`, `_`; регистр учитывается. Должен быть уникален среди сообщений текущего пользователя. Возвращается в `clientId` объекта Message — по нему клиент сопоставляет локальное (ещё не подтверждённое) сообщение с серверным, в т. ч. пришедшим через WebSocket раньше ответа |

#### Успешный ответ

| Поле      | Тип     | Описание                                               |
|-----------|---------|--------------------------------------------------------|
| `message` | Message | Объект [Message](#объект-message) отправленного сообщения |

```json
{
  "status": 1,
  "response": {
    "message": {
      "messageId": 15,
      "clientId": "6f1c2a9e-4b7d-4e3a-9c51-0d2f8b6a7e14",
      "conversationId": 1,
      "blockId": 2,
      "senderId": 1,
      "type": "text",
      "text": "Привет!",
      "isEdited": false,
      "createdAt": 1790846400,
      "updatedAt": 1790846400
    }
  },
  "actions": [
    { "type": "users", "data": { "userIds": [1] } }
  ]
}
```

Также отдаётся [action `users`](#action-users) с отправителем сообщения.

Участникам переписки рассылается WebSocket-событие [`messages` / `received`](#messages--received--новое-сообщение).

#### Ошибки

| Код  | Описание                                                                            |
|------|-------------------------------------------------------------------------------------|
| 1005 | Текст пустой или длиннее 4096 символов                                              |
| 1006 | Невалидный `clientId`                                                               |
| 2003 | Пользователь не авторизован                                                         |
| 5002 | Переписка не найдена, невалидный `conversationId` или пользователь в ней не состоит |
| 6004 | `clientId` уже использован для сообщения текущего пользователя в другой переписке   |

## Админ-панель

Страница `GET /admin` — веб-интерфейс для отправки сообщений от имени выбранного пользователя: поиск пользователя по имени или логину, выбор его диалога, ввод текста. Страница работает через методы ниже; клиентским приложениям они не нужны.

Доступ — по логину и паролю админа (пока захардкожены в `core/Admin.php`: `admin` / `admin`). Сессия админа ведётся через отдельную cookie `ADMINSESSID` и не связана с сессией пользователя (`PHPSESSID`): вход в админку не даёт доступа к пользовательским методам, и наоборот. Время жизни — как у пользовательской сессии.

Формат ответа и коды ошибок — общие (см. [Формат ответа](#формат-ответа), [Коды ошибок](#коды-ошибок)). Все методы, кроме `/admin/login`, без входа отвечают ошибкой 2003. Actions методы админки не отдают.

### POST /admin/login — Вход админа

| Поле       | Тип    | Обязательное | Описание     |
|------------|--------|--------------|--------------|
| `login`    | String | Да           | Логин админа |
| `password` | String | Да           | Пароль админа |

Успешный ответ — пустой `response`, устанавливается cookie `ADMINSESSID`. Ошибки: 2002 — неверный логин или пароль.

### POST /admin/logout — Выход админа

Завершает сессию админа. Успешный ответ — пустой `response`. Ошибки: 2003.

### GET /admin/getUsers — Поиск пользователей

| Поле    | Тип    | Обязательное | Описание                                                        |
|---------|--------|--------------|-----------------------------------------------------------------|
| `query` | String | Нет          | Подстрока для поиска по `name` или `login`; пусто — все пользователи |

| Поле ответа | Тип    | Описание                                                       |
|-------------|--------|----------------------------------------------------------------|
| `users`     | User[] | До 50 объектов [User](#объект-user) по возрастанию `userId`    |
| `hasNext`   | Bool   | Совпадений больше 50 — нужно уточнить запрос                   |

Ошибки: 1004 — `query` не строка, 2003.

### GET /admin/getConversations — Переписки пользователя

| Поле ответа | Тип     | Описание                                                  |
|-------------|---------|-----------------------------------------------------------|
| `message`   | Message | Объект [Message](#объект-message) отправленного сообщения |

Ошибки: 1005 — невалидный текст, 2003, 4001 — пользователь не найден или невалидный `userId`, 5002 — переписка не найдена, невалидный `conversationId` или пользователь в ней не состоит.

## WebSocket

WebSocket-соединение — канал, по которому сервер в реальном времени присылает клиенту события (новые сообщения, изменения и т. п.). Канал не гарантирует доставку: события, произошедшие, пока соединения не было, повторно не присылаются. Поэтому после каждого успешного (пере)подключения клиент синхронизирует актуальное состояние через REST-методы (см. [Синхронизация](#синхронизация)), а WebSocket использует только для обновлений «с этого момента».

### Подключение

1. Клиент получает [WebsocketConnectInfo](#объект-websocketconnectinfo):
   - при старте, после входа/выхода и при возврате из фона — из [`/global/start`](#get-globalstart--старт-работы-приложения). Если `websocketConnectInfo` равен `null` — пользователь не авторизован, подключаться не нужно (а открытое соединение нужно закрыть);
   - при переподключении — из [`/global/getWebsocketToken`](#get-globalgetwebsockettoken--токен-подключения-к-websocket). Ошибка `2003` — пользователь не авторизован, переподключаться не нужно.
2. Клиент открывает WebSocket-соединение по адресу `url` (без дополнительных параметров и заголовков). На некорректный запрос handshake сервер отвечает HTTP 400.
3. Первым сообщением клиент отправляет [`auth` / `connect`](#auth--connect--авторизация-соединения) с `userId` и `token`. Если оно не пришло в течение 10 секунд, сервер закрывает соединение с кодом `4002`.
4. Сервер отвечает [`auth` / `connected`](#auth--connected--соединение-авторизовано) — соединение готово — либо [`auth` / `connectionError`](#auth--connectionerror--ошибка-авторизации) и закрывает соединение. До `connected` сервер событий не присылает.
5. Клиент синхронизирует состояние через REST-методы.

Токен одноразовый и короткоживущий, поэтому **перед каждым подключением, включая переподключение, клиент получает новый токен**.

У одного пользователя может быть несколько одновременных соединений (несколько устройств или сессий); события пользователя рассылаются во все его соединения.

### Текущее соединение

В каждый момент у клиента не больше одного **текущего** соединения. Открывая новое соединение, клиент закрывает предыдущее (код `1000`) и с этого момента считает текущим новое.

Клиент обрабатывает события и закрытие **только текущего** соединения. Закрытие соединения, которое клиент сам закрыл или заменил новым, игнорируется — по нему не переподключаются и не меняют состояние авторизации. Пример: после входа под другим пользователем сервер закрывает соединения старой сессии с кодом `4003`, но клиент к этому моменту уже закрыл старое соединение и открыл новое — `4003` по старому соединению ничего не меняет.

### Синхронизация

Порядок: сначала `auth` / `connected`, затем REST-запросы. Так события, произошедшие во время синхронизации, не теряются — но могут прийти раньше ответа REST и оказаться новее его данных. Поэтому:

- события несут **полный объект** сущности (например, [Message](#объект-message) целиком), а не изменённые поля;
- клиент применяет события и данные REST **идемпотентно**: из двух версий одного объекта побеждает версия с большим `updatedAt`, при равенстве — любая. Повторное применение того же события ничего не меняет.
Это правило — обязательное требование к будущим событиям: событие без полного объекта с `updatedAt` в протокол не добавляется.

### Формат сообщений

Все сообщения в обе стороны — текстовые фреймы с JSON-объектом:

| Поле      | Тип    | Обязательное | Описание                                                                          |
|-----------|--------|--------------|-----------------------------------------------------------------------------------|
| `uid`     | String | Да           | Уникальный идентификатор сообщения — UUID v4, генерирует отправитель               |
| `group`   | String | Да           | Группа событий (`auth`, `events`, `conversations`, `messages`, …)                  |
| `event`   | String | Да           | Событие внутри группы                                                              |
| `body`    | Object | Да           | Данные события; состав зависит от пары `group` + `event`. Если данных нет — пустой объект `{}` |
| `userIds` | Int[]  | Нет          | Только в событиях сервера: идентификаторы пользователей, фигурирующих в событии (участники переписки, отправитель сообщения и т. п.), без повторов, по возрастанию. Если таких пользователей нет — поле отсутствует. Клиент обрабатывает его так же, как [action `users`](#action-users): недостающих в кэше (или устаревших) пользователей запрашивает через [`/users/getBatch`](#get-usersgetbatch--пользователи-по-списку-id) пачками до 100 |

```json
{
  "uid": "6f1c2a9e-4b7d-4e3a-9c51-0d2f8b6a7e14",
  "group": "auth",
  "event": "connected",
  "body": {}
}
```

Событие однозначно определяется парой `group` + `event`, далее записывается как `group` / `event`. Для каждого события описывается только содержимое `body`.

Правила:

- Клиент игнорирует события с неизвестными ему `group` или `event` (сервер будет добавлять новые).
- Сервер игнорирует неизвестные ему события от авторизованного клиента.
- Поле `userIds` в сообщениях клиента сервер игнорирует.
- Невалидный JSON, отсутствие любого из полей `uid`/`group`/`event`/`body` или неверный тип полей — ошибка протокола, сервер закрывает соединение с кодом `4000`.
- Максимальный размер сообщения от клиента — 64 КБ; при превышении сервер закрывает соединение с кодом `1009`.
- Бинарные фреймы не используются; полученный бинарный фрейм — ошибка протокола (`4000`).

### Подтверждение получения

На каждое событие сервера, **кроме группы `auth`**, клиент отвечает событием [`events` / `received`](#events--received--подтверждение-получения-события) с `uid` полученного события:

- подтверждение отправляется после того, как событие обработано (применено к локальному состоянию); загрузки пользователей по `userIds` ждать не нужно;
- события неизвестных клиенту `group` / `event` тоже подтверждаются — сразу, без обработки;
- подтверждение отправляется в то же соединение, из которого пришло событие; если соединение закрылось раньше, подтверждение не отправляется;
- на каждое событие — одно подтверждение; на повторно полученное событие с уже подтверждённым `uid` клиент отвечает повторно.

Сейчас сервер использует подтверждения для мониторинга доставки и неподтверждённые события повторно не отправляет — источником правды остаётся [синхронизация](#синхронизация) через REST. На подтверждения может опереться гарантированная доставка, если она появится.

### Поддержание соединения

Heartbeat инициирует **клиент**: каждые 25 секунд он отправляет protocol-level ping (фрейм ping по RFC 6455; на iOS — `URLSessionWebSocketTask.sendPing`, на Android — `pingInterval` в OkHttp). Сервер отвечает pong.

- Если pong не пришёл в течение 10 секунд, клиент считает соединение потерянным, закрывает его и переподключается.
- Если от клиента 60 секунд не приходило ни одного фрейма (ping, сообщения), сервер считает соединение мёртвым и разрывает его без close-фрейма — клиент увидит `1006`.
- Если клиент не успевает читать события и у сервера накопилось больше 1 МБ неотправленных данных соединения, сервер разрывает его без close-фрейма — клиент увидит `1006`.

Сервер сам ping не отправляет.

При уходе приложения в фон клиент закрывает соединение (код `1000`); при возврате из фона — вызывает `/global/start` и подключается заново.

### Коды закрытия соединения

Действия ниже относятся только к закрытию [текущего соединения](#текущее-соединение).

| Код  | Причина                                                                 | Действие клиента                                                   |
|------|-------------------------------------------------------------------------|--------------------------------------------------------------------|
| 1000 | Нормальное закрытие                                                     | Не переподключаться                                                 |
| 1001 | Сервер перезапускается / останавливается                                | Переподключиться с задержкой                                        |
| 1006 | Обрыв без кода (сеть, таймаут, переполнение буфера) — выставляется клиентской библиотекой | Переподключиться с задержкой                                        |
| 1009 | Слишком большое сообщение                                               | Ошибка клиента; переподключиться с задержкой                        |
| 1011 | Внутренняя ошибка сервера                                               | Переподключиться с задержкой                                        |
| 4000 | Ошибка протокола (невалидное сообщение, первое сообщение — не `auth` / `connect`, повторный `auth` / `connect`) | Ошибка клиента; переподключиться с задержкой |
| 4001 | Авторизация не удалась — перед закрытием сервер отправляет `auth` / `connectionError` | Действовать по `errorCode` из `connectionError`         |
| 4002 | Не получено `auth` / `connect` в течение 10 секунд                      | Переподключиться с задержкой                                        |
| 4003 | Сессия завершена (выход, повторный вход в той же сессии, удаление пользователя) | Не переподключаться автоматически; вызвать `/global/start` — если `websocketConnectInfo` равен `null`, перейти в неавторизованное состояние |

Переподключение — это получение токена через `/global/getWebsocketToken` и новое подключение. Задержка — экспоненциальная: 1, 2, 4, 8, 16, 30 секунд (дальше 30), со случайным разбросом ±20%; сбрасывается после успешного `auth` / `connected`. При появлении сети или возврате из фона клиент переподключается сразу, не дожидаясь задержки.

### События

#### `auth` / `connect` — авторизация соединения

Клиент → сервер. Должно быть первым сообщением в соединении; повторное `auth` / `connect` после успешной авторизации — ошибка протокола (`4000`).

| Поле `body` | Тип    | Описание                                                             |
|-------------|--------|----------------------------------------------------------------------|
| `userId`    | Int    | Идентификатор текущего пользователя                                  |
| `token`     | String | Токен подключения — `token` из [WebsocketConnectInfo](#объект-websocketconnectinfo) |

```json
{
  "uid": "0b8e7c3a-1d2f-4a6b-8c9d-5e4f3a2b1c0d",
  "group": "auth",
  "event": "connect",
  "body": {
    "userId": 1,
    "token": "3f9c1e0b8a7d4c2e9f6a5b4c3d2e1f0a3f9c1e0b8a7d4c2e9f6a5b4c3d2e1f0a"
  }
}
```

Сервер проверяет, что токен существует, не истёк, не использован и выдан пользователю `userId`. Токен гасится при любой попытке авторизации, даже неуспешной. При выходе, повторном входе и удалении пользователя токены сессии отзываются, поэтому отдельной проверки сессии нет — отозванный токен даёт `2004`.

Ответ — `auth` / `connected` или `auth` / `connectionError`.

#### `auth` / `connected` — соединение авторизовано

Сервер → клиент. Ответ на успешное `auth` / `connect`; после него сервер начинает присылать события.

`body` — пустой объект.

```json
{
  "uid": "6f1c2a9e-4b7d-4e3a-9c51-0d2f8b6a7e14",
  "group": "auth",
  "event": "connected",
  "body": {}
}
```

#### `auth` / `connectionError` — ошибка авторизации

Сервер → клиент. Ответ на неуспешное `auth` / `connect`; сразу после него сервер закрывает соединение с кодом `4001`.

| Поле `body` | Тип | Описание                                   |
|-------------|-----|--------------------------------------------|
| `errorCode` | Int | Код ошибки (см. таблицу ниже)              |

```json
{
  "uid": "9a2d4f6e-8b1c-4d3e-a5f7-2c4b6d8e0f1a",
  "group": "auth",
  "event": "connectionError",
  "body": { "errorCode": 2004 }
}
```

| Код  | Описание                                                                                      | Действие клиента                                        |
|------|-----------------------------------------------------------------------------------------------|---------------------------------------------------------|
| 1004 | Невалидные параметры: нет `userId` или `token`, неверный тип                                  | Ошибка клиента; переподключиться с задержкой             |
| 2004 | Токен не найден, истёк, уже использован, отозван или выдан другому пользователю               | Сразу получить новый токен через `/global/getWebsocketToken` и переподключиться; при повторе — с задержкой. Ошибка `2003` от `/global/getWebsocketToken` — перейти в неавторизованное состояние |
| 9001 | Внутренняя ошибка сервера                                                                     | Переподключиться с задержкой                             |

#### `events` / `received` — подтверждение получения события

Клиент → сервер. Отправляется на каждое событие сервера, кроме группы `auth` (см. [Подтверждение получения](#подтверждение-получения)). До `auth` / `connected` — ошибка протокола (`4000`), как и любое сообщение кроме `auth` / `connect`.

| Поле `body`   | Тип    | Описание                           |
|---------------|--------|------------------------------------|
| `receivedUid` | String | `uid` полученного события сервера  |

```json
{
  "uid": "c3e1a7b2-5d4f-4a8e-9b6c-1f2e3d4c5b6a",
  "group": "events",
  "event": "received",
  "body": { "receivedUid": "7d2b9e4f-1a3c-4e5d-8f6a-2b4c6d8e0a1b" }
}
```

Сервер не отвечает на подтверждение. Подтверждение с неизвестным или чужим `receivedUid` сервер игнорирует.

#### `conversations` / `singleCreated` — создана личная переписка

Сервер → клиент. Приходит всем участникам новой личной переписки (во все их соединения, включая соединения создателя), когда переписка создана методом [`/conversations/createSingle`](#post-conversationscreatesingle--создание-личной-переписки). Если метод вернул уже существующую переписку, событие не отправляется.

| Поле `body`    | Тип          | Описание                                                                                     |
|----------------|--------------|----------------------------------------------------------------------------------------------|
| `conversation` | Conversation | Объект [Conversation](#объект-conversation) созданной переписки — с точки зрения получателя (`opponentUserId` — собеседник получателя) |

`userIds` — участники переписки (`memberIds`).

```json
{
  "uid": "1e5f7a9c-3b2d-4c6e-8a0f-4d6b8c0e2a4f",
  "group": "conversations",
  "event": "singleCreated",
  "body": {
    "conversation": {
      "conversationId": 1,
      "type": "single",
      "memberIds": [1, 2],
      "name": null,
      "avatar": null,
      "opponentUserId": 1,
      "updatedAt": 1790846400
    }
  },
  "userIds": [1, 2]
}
```

#### `messages` / `received` — новое сообщение

Сервер → клиент. Приходит всем участникам переписки (во все их соединения, включая соединения отправителя), когда сообщение отправлено методом [`/messages/send`](#post-messagessend--отправка-сообщения).

| Поле `body` | Тип     | Описание                                              |
|-------------|---------|-------------------------------------------------------|
| `message`   | Message | Объект [Message](#объект-message) нового сообщения     |

`userIds` — отправитель сообщения (`senderId`).

```json
{
  "uid": "7d2b9e4f-1a3c-4e5d-8f6a-2b4c6d8e0a1b",
  "group": "messages",
  "event": "received",
  "body": {
    "message": {
      "messageId": 15,
      "clientId": "6f1c2a9e-4b7d-4e3a-9c51-0d2f8b6a7e14",
      "conversationId": 1,
      "blockId": 2,
      "senderId": 1,
      "type": "text",
      "text": "Привет!",
      "isEdited": false,
      "createdAt": 1790846400,
      "updatedAt": 1790846400
    }
  },
  "userIds": [1]
}
```

Отправитель получает событие и в том соединении, с устройства которого отправил сообщение: сообщение у него уже есть из ответа `/messages/send`, и по правилам [синхронизации](#синхронизация) повторное применение ничего не меняет. Событие может прийти и раньше ответа — локальное неподтверждённое сообщение клиент находит по `clientId` (вместе с `senderId`) и заменяет серверным. При повторе `/messages/send` с тем же `clientId` событие повторно не рассылается.

#### `messages` / `edited` — сообщение отредактировано

Сервер → клиент. Приходит всем участникам переписки (во все их соединения, включая соединения автора), когда сообщение изменено методом [`/messages/edit`](#post-messagesedit--редактирование-сообщения). Если текст не изменился, событие не отправляется.

| Поле `body` | Тип     | Описание                                                   |
|-------------|---------|------------------------------------------------------------|
| `message`   | Message | Обновлённый объект [Message](#объект-message)               |

`userIds` — отправитель сообщения (`senderId`).
