# Общие сведения

[← Документация API](../../API_Documentation.md)

Все методы принимают параметры POST-запросов в формате `application/x-www-form-urlencoded`, GET-параметры — через query string.

Сессия ведётся через cookie `PHPSESSID`. После успешной регистрации или входа сервер устанавливает cookie, которую необходимо передавать в последующих запросах.

Время жизни сессии — 30 дней с момента последнего запроса: каждый метод, требующий авторизации, продлевает сессию и переотправляет cookie с новым сроком действия. Клиент должен сохранять обновлённую cookie из ответа.

## Формат ответа

Успешный ответ:
```json
{ "status": 1, "response": { ... }, "actions": [ ... ] }
```

Поле `actions` опционально: оно есть только у успешных ответов и только если сервер передаёт клиенту дополнительные указания (см. [Actions](#actions)). Если actions нет, поле в ответе отсутствует.

Ответ с ошибкой:
```json
{ "status": 0, "errorCode": <int> }
```

При внутренней ошибке сервера ответ приходит с HTTP-статусом 500 и `errorCode` 9001.

## Actions

Action — указание клиенту, которое приходит в массиве `actions` успешного ответа вместе с основными данными. Все actions имеют одну структуру:

| Поле   | Тип    | Описание                                 |
|--------|--------|------------------------------------------|
| `type` | String | Тип action                               |
| `data` | Object | Данные action; формат зависит от `type`  |

Клиент должен игнорировать actions неизвестных ему типов.

### Action `users`

Пользователи, фигурирующие в ответе на текущий запрос (участники переписки, отправители сообщений и т. п.). Получив этот action, клиент проверяет наличие пользователей в своём локальном кэше и недостающих (или устаревших) запрашивает методом [`/users/getBatch`](methods/Users.md#get-usersgetbatch--пользователи-по-списку-id). Число id в action не ограничено, а `/users/getBatch` принимает не больше 100 за запрос — если нужно больше, клиент дозапрашивает пачками по 100.

| Поле `data` | Тип   | Описание                                         |
|-------------|-------|--------------------------------------------------|
| `userIds`   | Int[] | Идентификаторы пользователей, без повторов, по возрастанию |

```json
{
  "type": "users",
  "data": {
    "userIds": [1, 2]
  }
}
```

Если в ответе нет ни одного пользователя (например, пустой список сообщений), action не отдаётся.

Методы, отдающие action `users`:

| Метод                          | Какие пользователи                                     |
|--------------------------------|--------------------------------------------------------|
| `/conversations/createSingle`  | Участники переписки (`memberIds`)                      |
| `/conversations/getList`       | Участники всех переписок в выдаче (`memberIds`)        |
| `/messages/getList`            | Отправители сообщений в выдаче (`senderId`)            |
| `/messages/getBlock`           | Отправители сообщений блока (`senderId`)               |
| `/messages/send`               | Отправитель сообщения (`senderId`)                     |
| `/messages/edit`               | Отправитель сообщения (`senderId`)                     |
