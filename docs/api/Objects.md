## Объект User

| Поле      | Тип           | Описание                                              |
|-----------|---------------|-------------------------------------------------------|
| `userId` | Int           | Идентификатор пользователя                            |
| `login`   | String        | Логин                                                 |
| `name`    | String        | Отображаемое имя                                      |
| `avatar`  | File \| null  | Аватар — объект [File](#объект-file) типа `image` (опционально) |

```json
{

  "name": "Ivan Petrov",

    "size": 8293,

      "smallUrl": "http://localhost:8080/static/uploads/2026/09/952c7adde9fc838c66ee905324c1e8fa_small.jpg"
    }
  }
}
```

## Объект Conversation

| Поле             | Тип          | Описание                                                                 |
|------------------|--------------|--------------------------------------------------------------------------|
| `conversationId` | Int          | Идентификатор переписки                                                  |
| `type`           | String       | Тип переписки: `single` (личная) или `group` (групповая)                 |
| `memberIds`      | Int[] \| null | Идентификаторы участников личной переписки (по возрастанию); для `group` — `null`: состав группы — в [GroupInfo](#объект-groupinfo) |
| `name`           | String \| null | Название — только для `group`; для `single` всегда `null`             |
| `description`    | String \| null | Описание — только для `group`, опционально; для `single` всегда `null` |
| `avatar`         | File \| null   | Аватар — объект [File](#объект-file) типа `image`; только для `group`, опционально; для `single` всегда `null` |
| `opponentUserId` | Int \| null   | Идентификатор собеседника — только для `single` (второй участник относительно текущего пользователя); для `group` всегда `null`. Сам пользователь запрашивается через [`/users/getBatch`](methods/Users.md#get-usersgetbatch--пользователи-по-списку-id) по [action `users`](General.md#action-users) |
| `lastMessage`    | LastMessage \| null | Последнее сообщение переписки — объект [LastMessage](#объект-lastmessage); `null`, пока сообщений нет, а также если последнее сообщение удалено (например, вместе с удалённым пользователем). Меняется при отправке нового сообщения и при редактировании последнего |
| `positionUpdatedAt` | Int       | Время, когда переписка последний раз поднималась в списке, — `createdAt` последнего сообщения, до первого сообщения — время создания переписки. У группы — время последнего сообщения или время вступления текущего пользователя, что позже: добавленный в группу видит её наверху списка. Unix timestamp в миллисекундах. По нему (по убыванию) отсортирован [список переписок](methods/Conversations.md#get-conversationsgetlist--список-переписок) |
| `updatedInfoAt`  | Int          | Время последнего изменения информации о переписке, не меняющего её позицию: полей переписки (участники, название, аватар) и текста последнего сообщения. Новые сообщения его не меняют — их отражает `positionUpdatedAt`. Unix timestamp в миллисекундах |
| `unreadCount`    | Int          | Непрочитанные текущим пользователем сообщения переписки (см. [прочтение](#прочтение)) |
| `lastReadMessageId` | Int       | Последнее прочитанное текущим пользователем сообщение; `0` — ничего не прочитано |
| `changeVersion`  | Int          | [Версия пользователя](#версия-пользователя) на момент последнего изменения переписки для текущего пользователя (прочтение, новое сообщение, изменение информации; не позиция). Курсор фильтра [`changedAfter`](methods/Conversations.md#get-conversationsgetlist--список-переписок) и версия полей прочтения при [слиянии](WebSocket.md#слияние-переписки) |

Новая переписка сразу появляется в списке у всех участников — с `lastMessage: null` и `positionUpdatedAt`, равным времени создания.

`unreadCount`, `lastReadMessageId` и `changeVersion` зависят от текущего пользователя, как и `opponentUserId` (и `positionUpdatedAt` у группы).

Состав и роли группы в Conversation не входят: их изменение не меняет Conversation остальных участников и их версию. Они отдаются отдельно — [GroupInfo](#объект-groupinfo).

У переписки три независимые версии — позиция (`positionUpdatedAt` вместе с `lastMessage`), информация (`updatedInfoAt`) и прочтение (`changeVersion`); клиент сливает их по [правилам слияния переписки](WebSocket.md#слияние-переписки).

```json
{
  "conversationId": 1,
  "type": "single",
  "memberIds": [1, 2],
  "name": null,
  "description": null,
  "avatar": null,
  "opponentUserId": 2,
  "lastMessage": {
    "messageId": 15,
    "senderId": 1,
    "type": "text",
    "text": "Привет!",
    "updatedAt": 1790846400123
  },
  "positionUpdatedAt": 1790846400123,
  "updatedInfoAt": 1790846000456,
  "unreadCount": 0,
  "lastReadMessageId": 15,
  "changeVersion": 118
}
```

## Прочтение

Прочтение — указатель `lastReadMessageId` на пару (переписка, пользователь): всё, что с id не больше указателя, прочитано; отдельного статуса у каждого сообщения нет. Указатель только растёт — прочтение более старого сообщения ничего не меняет. Своё сообщение всегда прочитано: отправка сдвигает указатель отправителя на неё и тем самым отмечает прочитанной всю переписку до неё. Переписку отмечают прочитанной методом [`/conversations/markRead`](methods/Conversations.md#post-conversationsmarkread--отметка-прочтения). Указатели других участников — [MemberReadMeta](#объект-memberreadmeta).

## Версия пользователя

У каждого пользователя одна монотонная версия `changeVersion`: она растёт ровно на 1 с каждым изменением его переписок, кроме позиции в списке, — прочтением, новым сообщением, созданием переписки, изменением информации (в том числе правкой последнего сообщения). Изменение, которое затрагивает всех участников, увеличивает версию у каждого. Изменённая переписка получает новую версию пользователя в поле `changeVersion`.

Текущую версию вместе с общим счётчиком отдают [`/conversations/getList`](methods/Conversations.md#get-conversationsgetlist--список-переписок) и [`/global/getTotalUnreadCount`](methods/Global.md#get-globalgettotalunreadcount--общий-счётчик-непрочитанных). Каждое изменение приходит WebSocket-событием со своей версией — на этом держится курсор [синхронизации](WebSocket.md#курсор-синхронизации).

## Объект ReadInfo

Состояние прочтения одной переписки для текущего пользователя и его общий счётчик — снимок на одной версии. Отдаётся методами [`/conversations/markRead`](methods/Conversations.md#post-conversationsmarkread--отметка-прочтения), [`/messages/send`](methods/Messages.md#post-messagessend--отправка-сообщения) и событиями [`conversations` / `read`](websocket/Conversations.md#conversations--read--переписка-прочитана), [`messages` / `received`](websocket/Messages.md#messages--received--новое-сообщение).

| Поле                | Тип | Описание |
|---------------------|-----|----------|
| `conversationId`    | Int | Идентификатор переписки |
| `lastReadMessageId` | Int | Последнее прочитанное сообщение; `0` — ничего не прочитано (id сообщений начинаются с 1) |
| `unreadCount`       | Int | Непрочитанные в переписке |
| `totalUnreadCount`  | Int | Непрочитанные по всем перепискам пользователя |
| `changeVersion`     | Int | [Версия пользователя](#версия-пользователя), на которой сняты все поля выше; в событии — версия именно этого изменения |

```json
{
  "conversationId": 1,
  "lastReadMessageId": 15,
  "unreadCount": 0,
  "totalUnreadCount": 3,
  "changeVersion": 118
}
```

Клиент хранит `changeVersion` у каждой переписки и отдельно у общего счётчика. Поля прочтения переписки (`unreadCount`, `lastReadMessageId`, `changeVersion`) он берёт, если пришедший `changeVersion` больше её локального; `totalUnreadCount` — если больше локальной версии счётчика. Шкала одна, поэтому счётчик из события по любой переписке корректно сравнивается со счётчиком из `getList` и `getTotalUnreadCount`. Переписку, которой нет в загруженном списке, по ReadInfo не загружают, но общий счётчик применяют.

## Объект MemberReadMeta

Указатель [прочтения](#прочтение) другого участника переписки — для статуса «прочитано» у сообщений. Отдаётся методом [`/conversations/getMembersReadMeta`](methods/Conversations.md#get-conversationsgetmembersreadmeta--прочтение-другими-участниками); изменения приходят событием [`conversations` / `memberRead`](websocket/Conversations.md#conversations--memberread--участник-прочитал-переписку).

| Поле                | Тип | Описание |
|---------------------|-----|----------|
| `userId`            | Int | Идентификатор участника |
| `lastReadMessageId` | Int | Последнее прочитанное участником сообщение; `0` — ничего не прочитано |

```json
{
  "userId": 2,
  "lastReadMessageId": 15
}
```

Версии у объекта нет: указатель только растёт, поэтому из нескольких значений для одного участника клиент берёт **максимум**. Не путать с [ReadInfo](#объект-readinfo) — собственным состоянием прочтения текущего пользователя со счётчиками и версией. Свой указатель текущий пользователь берёт только из Conversation и ReadInfo.

Сообщение прочитано участником, если его `messageId <= lastReadMessageId` этого участника. В личной переписке своё сообщение прочитано, если указатель собеседника не меньше его id. В группе учитываются только участники из текущей [GroupInfo](#объект-groupinfo), вступившие до сообщения (`joinedAfterMessageId < messageId`): прочитано кем-то — хотя бы один их указатель не меньше id, всеми — минимум их указателей, список прочитавших — они же. Новому участнику указатель ставится на последнее сообщение группы, но сообщения до его вступления им не считаются прочитанными.

## Объект GroupInfo

Состав и роли группы. Отдаётся методами [`/groups/*`](methods/Groups.md) и событиями группы [`groups`](websocket/Groups.md).

| Поле             | Тип           | Описание |
|------------------|---------------|----------|
| `conversationId` | Int           | Группа |
| `version`        | Int           | Версия GroupInfo: растёт при каждом изменении состава или владельца. Своя у каждой группы, не связана с [версией пользователя](#версия-пользователя) |
| `members`        | GroupMember[] | Все участники, включая владельца, — объекты [GroupMember](#объект-groupmember), по возрастанию `userId` |

```json
{
  "conversationId": 12,
  "version": 4,
  "members": [
    { "userId": 1, "role": "owner", "joinedAfterMessageId": 0 },
    { "userId": 2, "role": "member", "joinedAfterMessageId": 0 },
    { "userId": 5, "role": "member", "joinedAfterMessageId": 318 }
  ]
}
```

Правила клиента:

- **Когда запрашивать.** При открытии экрана группы — сначала показать сохранённую GroupInfo, если есть, затем [`/groups/getInfo`](methods/Groups.md#get-groupsgetinfo--состав-группы); после каждого переподключения WebSocket (`auth` / `connected`), пока экран открыт. GroupInfo хранится локально и показывается в оффлайне.
- **Слияние.** Пришедшая GroupInfo (ответ или событие) заменяет локальную целиком, если её `version` больше локальной. Порядок прихода не важен.
- **События.** GroupInfo из событий применяется, если группа открыта или её GroupInfo уже сохранена; для других групп событие GroupInfo не создаёт. Сохранённая GroupInfo закрытой группы может устареть за время разрыва — это исправит запрос при следующем открытии.
- **Права.** Кнопки владельца клиент показывает по роли. Окончательно права проверяет сервер (`5004`).
- **Выход.** Перед [`/groups/leave`](methods/Groups.md#post-groupsleave--выход-из-группы) владельцу показывается предупреждение, что владелец будет назначен автоматически; единственному участнику — что в группе никого не останется и переписка станет недоступна.
- **Мета прочтения.** Участников, которых нет в текущей GroupInfo, клиент в статусе «прочитано» не учитывает и при новой GroupInfo убирает из локальной [меты](#объект-memberreadmeta).

## Объект GroupMember

| Поле                   | Тип    | Описание |
|------------------------|--------|----------|
| `userId`               | Int    | Участник |
| `role`                 | String | `owner` — владелец (ровно один), `member` — участник. Список будет расширяться; неизвестную роль клиент показывает как `member` |
| `joinedAfterMessageId` | Int    | Последнее сообщение группы на момент вступления (`0` — вступил до первого сообщения). Сообщения с большим `messageId` отправлены после вступления — только по ним участник учитывается в статусе «прочитано» |

## Объект RemovedConversation

Метка: текущий пользователь перестал быть участником переписки (удалён из группы или вышел). Отдаётся методами [`/conversations/getList`](methods/Conversations.md#get-conversationsgetlist--список-переписок) (`changedAfter`) и [`/groups/leave`](methods/Groups.md#post-groupsleave--выход-из-группы), событиями [`groups` / `membersRemoved`](websocket/Groups.md#groups--membersremoved--участники-удалены) и [`memberLeft`](websocket/Groups.md#groups--memberleft--участник-вышел).

| Поле             | Тип | Описание |
|------------------|-----|----------|
| `conversationId` | Int | Переписка |
| `changeVersion`  | Int | [Версия пользователя](#версия-пользователя), на которой он перестал быть участником |

```json
{
  "conversationId": 12,
  "changeVersion": 131
}
```

Правила клиента:

- **Применение.** Если переписка загружена и её локальный `changeVersion` меньше пришедшего — клиент удаляет её из списка вместе с локальным кэшем (сообщения, мета прочтения, GroupInfo, ссылка в `pendingConversationIds` — см. [`membersAdded`](websocket/Groups.md#groups--membersadded--участники-добавлены)). Если пришедшая версия меньше локальной — пользователя уже добавили обратно, метка устарела и игнорируется.
- **Локальная метка.** Применённую метку клиент сохраняет — `removedVersions[conversationId] = changeVersion`, **в том числе по незагруженной переписке**. Любая пришедшая версия этой переписки (ответы `getList`, `getBatch`, события) с `changeVersion` не больше метки отбрасывается; версия больше — повторное добавление: переписка принимается, метка снимается. Так ответ REST, собранный до удаления и пришедший после события удаления, не вернёт переписку в список. Метки хранятся вместе со списком переписок и сбрасываются вместе с ним (полная перезагрузка списка, выход из аккаунта).
- **Пропущенное удаление.** Если метод по известной клиенту группе ответил `5002` (`/groups/getInfo`, `/messages/getList`, `/messages/send`, `/conversations/markRead`, `/conversations/getMembersReadMeta`) или `6002` (`/messages/getBlock`), клиент запрашивает её через [`/conversations/getBatch`](methods/Conversations.md#get-conversationsgetbatch--переписки-по-списку-id). Переписка в `notFoundIds` — пользователь больше не участник: клиент удаляет её с меткой на её локальной версии (`removedVersions[conversationId]` = локальный `changeVersion`), не дожидаясь синхронизации; настоящая метка придёт через `removedConversations`.
- **Общий счётчик.** Вместе с меткой в событиях и ответе `leave` приходит `totalUnreadCount` — счётчик после вычета непрочитанных группы, на версии метки; применяется по правилам [ReadInfo](#объект-readinfo).

## Объект UserErrorInfo

Пользователь, по которому действие не выполнено, и причина. Отдаётся методами [`/groups/addMembers`](methods/Groups.md#post-groupsaddmembers--добавление-участников) и [`/groups/removeMembers`](methods/Groups.md#post-groupsremovemembers--удаление-участников).

| Поле        | Тип | Описание |
|-------------|-----|----------|
| `userId`    | Int | Пользователь из запроса |
| `errorCode` | Int | Причина — код из [Errors.md](Errors.md) |

```json
{
  "userId": 7,
  "errorCode": 5006
}
```

## Объект LastMessage

Краткое представление последнего сообщения переписки для списка чатов.

| Поле        | Тип            | Описание                                                                 |
|-------------|----------------|--------------------------------------------------------------------------|
| `messageId` | Int            | Идентификатор сообщения ([Message](#объект-message).`messageId`)          |
| `senderId`  | Int            | Отправитель — для подписи превью («Иван: привет»); попадает в [action `users`](General.md#action-users) методов, отдающих Conversation |
| `type`      | String         | Тип сообщения — как `Message.type` (пока только `text`)                  |
| `text`      | String \| null | Текст сообщения; `null` для типов без текста (появятся позже)            |
| `updatedAt` | Int            | Время последнего изменения сообщения — как `Message.updatedAt`, Unix timestamp в миллисекундах. Версия LastMessage при [слиянии](WebSocket.md#слияние-переписки) |

Время отправки в LastMessage не входит — это `positionUpdatedAt` переписки.

```json
{
  "messageId": 15,
  "senderId": 1,
  "type": "text",
  "text": "Привет!",
  "updatedAt": 1790846400123
}
```

## Объект Message

| Поле             | Тип    | Описание                                                              |
|------------------|--------|-----------------------------------------------------------------------|
| `messageId`      | Int    | Идентификатор сообщения                                               |
| `clientId`       | String | Идентификатор, сгенерированный клиентом при отправке (см. [`/messages/send`](methods/Messages.md#post-messagessend--отправка-сообщения)); уникален в пределах отправителя. У сообщений, отправленных до появления поля, и у сообщений из админки — UUID, сгенерированный сервером |
| `conversationId` | Int    | Идентификатор переписки                                               |
| `blockId`        | Int    | Идентификатор блока, в котором лежит сообщение (см. [блоки сообщений](#блоки-сообщений)) |
| `senderId`       | Int    | Идентификатор пользователя, отправившего сообщение                    |
| `type`           | String | Тип сообщения: пока только `text`                                      |
| `text`           | String | Текст сообщения                                                       |
| `isEdited`       | Bool   | Было ли сообщение отредактировано                                     |
| `createdAt`      | Int    | Время создания — Unix timestamp в миллисекундах                       |
| `updatedAt`      | Int    | Время последнего изменения — Unix timestamp в миллисекундах; у неотредактированного сообщения равно `createdAt` |

```json
{
  "messageId": 15,
  "clientId": "6f1c2a9e-4b7d-4e3a-9c51-0d2f8b6a7e14",
  "conversationId": 1,
  "blockId": 2,
  "senderId": 1,
  "type": "text",
  "text": "Привет!",
  "isEdited": false,
  "createdAt": 1790846400123,
  "updatedAt": 1790846400123
}
```

## Блоки сообщений

Сообщения переписки хранятся блоками по 20 штук в порядке отправки: новое сообщение попадает в последний блок переписки, а если он заполнен — в новый. Идентификаторы блоков одной переписки возрастают от старых к новым. Заполненным может быть не только последний блок.

Блок может быть пустым, если из него удалили все сообщения. Блоки не удаляются, а место удалённого сообщения остаётся занятым: в блок, кроме последнего, новые сообщения не попадают, и границы блоков не сдвигаются.

## Объект MessageBlock

Блок с сообщениями — отдаётся методом [`/messages/getBlockBatch`](methods/Messages.md#get-messagesgetblockbatch--сообщения-нескольких-блоков).

| Поле             | Тип         | Описание |
|------------------|-------------|----------|
| `blockId`        | Int         | Идентификатор блока |
| `conversationId` | Int         | Идентификатор переписки |
| `messages`       | Message[]   | Все сообщения блока — объекты [Message](#объект-message), от новых к старым; пустой массив — все сообщения блока удалены |
| `updatedAt`      | Int \| null | Время последнего изменения или удаления сообщений блока — Unix timestamp в миллисекундах; `null` — не менялись. Новые сообщения его не меняют |

```json
{
  "blockId": 3,
  "conversationId": 1,
  "messages": [],
  "updatedAt": 1790849500000
}
```

## Объект WebsocketConnectInfo

Данные для подключения к [WebSocket](WebSocket.md). Отдаётся методами [`/global/start`](methods/Global.md#get-globalstart--старт-работы-приложения) и [`/global/getWebsocketToken`](methods/Global.md#get-globalgetwebsockettoken--токен-подключения-к-websocket).

| Поле        | Тип    | Описание                                                                                              |
|-------------|--------|-------------------------------------------------------------------------------------------------------|
| `url`       | String | Адрес WebSocket-сервера (`ws://` или `wss://`). Клиент не должен хранить его между вызовами — адрес может меняться |
| `token`     | String | Токен подключения: одноразовый (гасится при первой попытке авторизации соединения, даже неуспешной), привязан к текущему пользователю и текущей сессии |
| `expiresIn` | Int    | Сколько секунд токен действителен с момента выдачи (сейчас 120). Отсчитывается от получения ответа по монотонным часам, а не по системному времени устройства. Окончательный признак негодного токена — ошибка `2004` при подключении |

```json
{
  "url": "wss://example.com/ws",
  "token": "3f9c1e0b8a7d4c2e9f6a5b4c3d2e1f0a3f9c1e0b8a7d4c2e9f6a5b4c3d2e1f0a",
  "expiresIn": 120
}
```
