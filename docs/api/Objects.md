## Объект User

| Поле      | Тип           | Описание                                              |
|-----------|---------------|-------------------------------------------------------|
| `userId` | Int           | Идентификатор пользователя                            |
| `login`   | String        | Логин                                                 |
| `name`    | String        | Отображаемое имя                                      |
| `avatar`  | File \| null  | Аватар — объект [File](#объект-file) типа `image` (опционально) |

```json
{
  "userId": 1,
  "login": "ivan",
  "name": "Ivan Petrov",
  "avatar": {
    "fileId": 1,
    "type": "image",
    "url": "http://localhost:8080/static/uploads/2026/09/952c7adde9fc838c66ee905324c1e8fa.jpg",
    "size": 8293,
    "filename": "avatar.jpg",
    "extension": "jpg",
    "data": {
      "smallUrl": "http://localhost:8080/static/uploads/2026/09/952c7adde9fc838c66ee905324c1e8fa_small.jpg"
    }
  }
}
```

## Объект File

| Поле        | Тип    | Описание                                                        |
|-------------|--------|-----------------------------------------------------------------|
| `fileId`   | Int    | Идентификатор файла                                             |
| `type`      | String | Тип файла: `image` или `other` (список будет расширяться)        |
| `url`       | String | Ссылка на файл                                                  |
| `size`      | Int    | Размер в байтах                                                 |
| `filename`  | String | Имя файла                                                       |
| `extension` | String | Расширение файла; если расширения нет — `"file"`                |
| `data`      | Object | Дополнительная информация, состав зависит от `type` (см. ниже)   |

`data` для `other` — пустой объект `{}`.

`data` для `image`:

| Поле        | Тип    | Описание                                                                        |
|-------------|--------|---------------------------------------------------------------------------------|
| `smallUrl` | String | Ссылка на уменьшенную копию: не более 200 пикселей по меньшей стороне           |

```json
{
  "fileId": 1,
  "type": "image",
  "url": "http://localhost:8080/static/uploads/2026/09/952c7adde9fc838c66ee905324c1e8fa.jpg",
  "size": 8293,
  "filename": "photo.jpg",
  "extension": "jpg",
  "data": {
    "smallUrl": "http://localhost:8080/static/uploads/2026/09/952c7adde9fc838c66ee905324c1e8fa_small.jpg"
  }
}
```

## Объект Conversation

| Поле             | Тип          | Описание                                                                 |
|------------------|--------------|--------------------------------------------------------------------------|
| `conversationId` | Int          | Идентификатор переписки                                                  |
| `type`           | String       | Тип переписки: `single` (личная) или `group` (групповая)                 |
| `memberIds`      | Int[]        | Идентификаторы пользователей, состоящих в переписке (по возрастанию)     |
| `name`           | String \| null | Название — только для `group`; для `single` всегда `null`             |
| `avatar`         | File \| null   | Аватар — объект [File](#объект-file) типа `image`; только для `group`, опционально; для `single` всегда `null` |
| `opponentUserId` | Int \| null   | Идентификатор собеседника — только для `single` (второй участник относительно текущего пользователя); для `group` всегда `null`. Сам пользователь запрашивается через [`/users/getBatch`](methods/Users.md#get-usersgetbatch--пользователи-по-списку-id) по [action `users`](General.md#action-users) |
| `lastMessage`    | LastMessage \| null | Последнее сообщение переписки — объект [LastMessage](#объект-lastmessage); `null`, пока сообщений нет, а также если последнее сообщение удалено (например, вместе с удалённым пользователем). Меняется при отправке нового сообщения и при редактировании последнего |
| `positionUpdatedAt` | Int       | Время, когда переписка последний раз поднималась в списке, — `createdAt` последнего сообщения, до первого сообщения — время создания переписки. Unix timestamp в миллисекундах. По нему (по убыванию) отсортирован [список переписок](methods/Conversations.md#get-conversationsgetlist--список-переписок) |
| `updatedInfoAt`  | Int          | Время последнего изменения информации о переписке, не меняющего её позицию: полей переписки (участники, название, аватар) и текста последнего сообщения. Новые сообщения его не меняют — их отражает `positionUpdatedAt`. Unix timestamp в миллисекундах |
| `unreadCount`    | Int          | Непрочитанные текущим пользователем сообщения переписки (см. [прочтение](#прочтение)) |
| `lastReadMessageId` | Int       | Последнее прочитанное текущим пользователем сообщение; `0` — ничего не прочитано |
| `changeVersion`  | Int          | [Версия пользователя](#версия-пользователя) на момент последнего изменения переписки для текущего пользователя (прочтение, новое сообщение, изменение информации; не позиция). Курсор фильтра [`changedAfter`](methods/Conversations.md#get-conversationsgetlist--список-переписок) и версия полей прочтения при [слиянии](WebSocket.md#слияние-переписки) |

Новая переписка сразу появляется в списке у всех участников — с `lastMessage: null` и `positionUpdatedAt`, равным времени создания.

`unreadCount`, `lastReadMessageId` и `changeVersion` зависят от текущего пользователя, как и `opponentUserId`.

У переписки три независимые версии — позиция (`positionUpdatedAt` вместе с `lastMessage`), информация (`updatedInfoAt`) и прочтение (`changeVersion`); клиент сливает их по [правилам слияния переписки](WebSocket.md#слияние-переписки).

```json
{
  "conversationId": 1,
  "type": "single",
  "memberIds": [1, 2],
  "name": null,
  "avatar": null,
  "opponentUserId": 2,
  "lastMessage": {
    "messageId": 15,
    "type": "text",
    "text": "Привет!",
    "updatedAt": 1790846400123
  },
  "positionUpdatedAt": 1790846400123,
  "updatedInfoAt": 1790846000456,
  "unreadCount": 0,
  "lastReadMessageId": 15,
  "changeVersion": 118
}
```

## Прочтение

Прочтение — указатель `lastReadMessageId` на пару (переписка, пользователь): всё, что с id не больше указателя, прочитано; отдельного статуса у каждого сообщения нет. Указатель только растёт — прочтение более старого сообщения ничего не меняет. Своё сообщение всегда прочитано: отправка сдвигает указатель отправителя на неё и тем самым отмечает прочитанной всю переписку до неё. Переписку отмечают прочитанной методом [`/conversations/markRead`](methods/Conversations.md#post-conversationsmarkread--отметка-прочтения). Указатели других участников — [MemberReadMeta](#объект-memberreadmeta).

## Версия пользователя

У каждого пользователя одна монотонная версия `changeVersion`: она растёт ровно на 1 с каждым изменением его переписок, кроме позиции в списке, — прочтением, новым сообщением, созданием переписки, изменением информации (в том числе правкой последнего сообщения). Изменение, которое затрагивает всех участников, увеличивает версию у каждого. Изменённая переписка получает новую версию пользователя в поле `changeVersion`.

Текущую версию вместе с общим счётчиком отдают [`/conversations/getList`](methods/Conversations.md#get-conversationsgetlist--список-переписок) и [`/global/getTotalUnreadCount`](methods/Global.md#get-globalgettotalunreadcount--общий-счётчик-непрочитанных). Каждое изменение приходит WebSocket-событием со своей версией — на этом держится курсор [синхронизации](WebSocket.md#курсор-синхронизации).

## Объект ReadInfo

Состояние прочтения одной переписки для текущего пользователя и его общий счётчик — снимок на одной версии. Отдаётся методами [`/conversations/markRead`](methods/Conversations.md#post-conversationsmarkread--отметка-прочтения), [`/messages/send`](methods/Messages.md#post-messagessend--отправка-сообщения) и событиями [`conversations` / `read`](websocket/Conversations.md#conversations--read--переписка-прочитана), [`messages` / `received`](websocket/Messages.md#messages--received--новое-сообщение).

| Поле                | Тип | Описание |
|---------------------|-----|----------|
| `conversationId`    | Int | Идентификатор переписки |
| `lastReadMessageId` | Int | Последнее прочитанное сообщение; `0` — ничего не прочитано (id сообщений начинаются с 1) |
| `unreadCount`       | Int | Непрочитанные в переписке |
| `totalUnreadCount`  | Int | Непрочитанные по всем перепискам пользователя |
| `changeVersion`     | Int | [Версия пользователя](#версия-пользователя), на которой сняты все поля выше; в событии — версия именно этого изменения |

```json
{
  "conversationId": 1,
  "lastReadMessageId": 15,
  "unreadCount": 0,
  "totalUnreadCount": 3,
  "changeVersion": 118
}
```

Клиент хранит `changeVersion` у каждой переписки и отдельно у общего счётчика. Поля прочтения переписки (`unreadCount`, `lastReadMessageId`, `changeVersion`) он берёт, если пришедший `changeVersion` больше её локального; `totalUnreadCount` — если больше локальной версии счётчика. Шкала одна, поэтому счётчик из события по любой переписке корректно сравнивается со счётчиком из `getList` и `getTotalUnreadCount`. Переписку, которой нет в загруженном списке, по ReadInfo не загружают, но общий счётчик применяют.

## Объект MemberReadMeta

Указатель [прочтения](#прочтение) другого участника переписки — для статуса «прочитано» у сообщений. Отдаётся методом [`/conversations/getMembersReadMeta`](methods/Conversations.md#get-conversationsgetmembersreadmeta--прочтение-другими-участниками); изменения приходят событием [`conversations` / `memberRead`](websocket/Conversations.md#conversations--memberread--участник-прочитал-переписку).

| Поле                | Тип | Описание |
|---------------------|-----|----------|
| `userId`            | Int | Идентификатор участника |
| `lastReadMessageId` | Int | Последнее прочитанное участником сообщение; `0` — ничего не прочитано |

```json
{
  "userId": 2,
  "lastReadMessageId": 15
}
```

Версии у объекта нет: указатель только растёт, поэтому из нескольких значений для одного участника клиент берёт **максимум**. Не путать с [ReadInfo](#объект-readinfo) — собственным состоянием прочтения текущего пользователя со счётчиками и версией. Свой указатель текущий пользователь берёт только из Conversation и ReadInfo.

Сообщение прочитано участником, если его `messageId <= lastReadMessageId` этого участника. В личной переписке своё сообщение прочитано, если указатель собеседника не меньше его id; в группе — прочитано кем-то (хотя бы один указатель), всеми (минимум указателей) и список прочитавших.

## Объект LastMessage

Краткое представление последнего сообщения переписки для списка чатов.

| Поле        | Тип            | Описание                                                                 |
|-------------|----------------|--------------------------------------------------------------------------|
| `messageId` | Int            | Идентификатор сообщения ([Message](#объект-message).`messageId`)          |
| `type`      | String         | Тип сообщения — как `Message.type` (пока только `text`)                  |
| `text`      | String \| null | Текст сообщения; `null` для типов без текста (появятся позже)            |
| `updatedAt` | Int            | Время последнего изменения сообщения — как `Message.updatedAt`, Unix timestamp в миллисекундах. Версия LastMessage при [слиянии](WebSocket.md#слияние-переписки) |

Время отправки в LastMessage не входит — это `positionUpdatedAt` переписки.

```json
{
  "messageId": 15,
  "type": "text",
  "text": "Привет!",
  "updatedAt": 1790846400123
}
```

```json
  "createdAt": 1790846400123,

```

## Блоки сообщений

Сообщения переписки хранятся блоками по 20 штук в порядке отправки: новое сообщение попадает в последний блок переписки, а если он заполнен — в новый. Идентификаторы блоков одной переписки возрастают от старых к новым. Заполненным может быть не только последний блок.

Блок может быть пустым, если из него удалили все сообщения. Блоки не удаляются, а место удалённого сообщения остаётся занятым: в блок, кроме последнего, новые сообщения не попадают, и границы блоков не сдвигаются.

## Объект MessageBlock

Блок с сообщениями — отдаётся методом [`/messages/getBlockBatch`](methods/Messages.md#get-messagesgetblockbatch--сообщения-нескольких-блоков).

| Поле             | Тип         | Описание |
|------------------|-------------|----------|
| `blockId`        | Int         | Идентификатор блока |
| `conversationId` | Int         | Идентификатор переписки |
| `messages`       | Message[]   | Все сообщения блока — объекты [Message](#объект-message), от новых к старым; пустой массив — все сообщения блока удалены |
| `updatedAt`      | Int \| null | Время последнего изменения или удаления сообщений блока — Unix timestamp в миллисекундах; `null` — не менялись. Новые сообщения его не меняют |

```json
{
  "blockId": 3,
  "conversationId": 1,
  "messages": [],
  "updatedAt": 1790849500000
}
```

## Объект WebsocketConnectInfo

Данные для подключения к [WebSocket](WebSocket.md). Отдаётся методами [`/global/start`](methods/Global.md#get-globalstart--старт-работы-приложения) и [`/global/getWebsocketToken`](methods/Global.md#get-globalgetwebsockettoken--токен-подключения-к-websocket).

| Поле        | Тип    | Описание                                                                                              |
|-------------|--------|-------------------------------------------------------------------------------------------------------|
| `url`       | String | Адрес WebSocket-сервера (`ws://` или `wss://`). Клиент не должен хранить его между вызовами — адрес может меняться |
| `token`     | String | Токен подключения: одноразовый (гасится при первой попытке авторизации соединения, даже неуспешной), привязан к текущему пользователю и текущей сессии |
| `expiresIn` | Int    | Сколько секунд токен действителен с момента выдачи (сейчас 120). Отсчитывается от получения ответа по монотонным часам, а не по системному времени устройства. Окончательный признак негодного токена — ошибка `2004` при подключении |

```json
{
  "url": "wss://example.com/ws",
  "token": "3f9c1e0b8a7d4c2e9f6a5b4c3d2e1f0a3f9c1e0b8a7d4c2e9f6a5b4c3d2e1f0a",
  "expiresIn": 120
}
```
