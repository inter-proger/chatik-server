# Групповые чаты: изменения API

[← Изменения API](../Changes.md)

Дата: 2026-10-22. Совместимость: **ломающее изменение** — `Conversation.memberIds` может быть `null` (только у групп, которых раньше не было).

## Коротко

Появились групповые переписки (`type: "group"`): до 100 участников, владелец с правами на добавление, удаление и передачу владения, выход из группы. Состав и роли группы — отдельный объект GroupInfo, он запрашивается при открытии группы и обновляется событиями, в Conversation группы его нет. Удаление из группы приходит событием и, после оффлайна, — метками в синхронизации списка.

## Ломающие изменения

- [`Conversation.memberIds`](../Objects.md#объект-conversation) — тип `Int[]` → `Int[] | null`: у групп `null`, у личных переписок по-прежнему оба участника. Клиент со строгой десериализацией должен сделать поле nullable до того, как пользователи начнут получать группы — иначе группа в ответе `getList` сломает разбор всего списка. Состав группы брать из [GroupInfo](../Objects.md#объект-groupinfo).
- Правило протокола в [синхронизации](../WebSocket.md#синхронизация): вместо «событие несёт полный объект» — «событие несёт версию и применяется идемпотентно» (полный объект или ссылка с версией, по которой клиент делает запрос). Существующие события не изменились; новые события `groups` пользуются обеими формами.

## Новое и изменённое

- Методы:
  - [`/groups/create`](../methods/Groups.md#post-groupscreate--создание-группы), [`/groups/addMembers`](../methods/Groups.md#post-groupsaddmembers--добавление-участников), [`/groups/removeMembers`](../methods/Groups.md#post-groupsremovemembers--удаление-участников), [`/groups/changeOwner`](../methods/Groups.md#post-groupschangeowner--передача-владения), [`/groups/getInfo`](../methods/Groups.md#get-groupsgetinfo--состав-группы), [`/groups/leave`](../methods/Groups.md#post-groupsleave--выход-из-группы) — новые.
  - [`/conversations/getList`](../methods/Conversations.md#get-conversationsgetlist--список-переписок) — новое поле `removedConversations` (с `changedAfter` — метки удаления, иначе пустой массив); с `changedAfter` `count` и `hasNext` считаются по перепискам и меткам вместе, следующая страница — по наибольшему `changeVersion` из обеих частей. Action `users` теперь включает отправителей последних сообщений (так же в `getBatch`).
  - [`/conversations/getMembersReadMeta`](../methods/Conversations.md#get-conversationsgetmembersreadmeta--прочтение-другими-участниками) — отдаёт action `users` с участниками из ответа.
- Объекты:
  - [Conversation](../Objects.md#объект-conversation) — новое поле `description`; `memberIds` у групп `null`; `positionUpdatedAt` у группы — время последнего сообщения или время вступления текущего пользователя, что позже.
  - [LastMessage](../Objects.md#объект-lastmessage) — новое поле `senderId`, для подписи превью в списке групп.
  - [GroupInfo](../Objects.md#объект-groupinfo), [GroupMember](../Objects.md#объект-groupmember), [RemovedConversation](../Objects.md#объект-removedconversation), [UserErrorInfo](../Objects.md#объект-usererrorinfo) — новые.
- Коды ошибок ([Errors.md](../Errors.md)): `1007` — невалидное описание группы; `5003`–`5008` — ошибки групп; `1003` теперь возвращается и для названия группы; `5002` — в методах групп и при удалении из группы во время запроса.
- WS-события:
  - [`groups` / `created`](../websocket/Groups.md#groups--created--группа-создана), [`membersAdded`](../websocket/Groups.md#groups--membersadded--участники-добавлены), [`membersRemoved`](../websocket/Groups.md#groups--membersremoved--участники-удалены), [`memberLeft`](../websocket/Groups.md#groups--memberleft--участник-вышел), [`ownerChanged`](../websocket/Groups.md#groups--ownerchanged--владелец-сменился) — новые.
  - [`conversations` / `memberRead`](../websocket/Conversations.md#conversations--memberread--участник-прочитал-переписку) — теперь с `userIds: [userId]`.

## Что сделать клиенту

1. **Модели.** Сделать `Conversation.memberIds` nullable, добавить `Conversation.description` и `LastMessage.senderId`, новые объекты GroupInfo, GroupMember, RemovedConversation, UserErrorInfo. Неизвестную роль `GroupMember.role` показывать как `member`.
2. **Список чатов.** Группа — по `name` и `avatar`; превью последнего сообщения подписывать отправителем (`lastMessage.senderId`, пользователь приходит в action `users`). Позицию брать из `positionUpdatedAt` как раньше — добавленному в группу она придёт со временем вступления.
3. **Экран группы.** При открытии показать сохранённую GroupInfo и запросить [`/groups/getInfo`](../methods/Groups.md#get-groupsgetinfo--состав-группы); повторять запрос после каждого `auth` / `connected`, пока экран открыт. GroupInfo из ответов и событий заменяет локальную только при большей `version`. Кнопки владельца — по роли `owner`.
4. **Создание и состав.** После `addMembers` / `removeMembers` показать число не добавленных или не удалённых из `notAddedUsersInfo` / `notRemovedUsersInfo` и подробности по запросу. Перед [`/groups/leave`](../methods/Groups.md#post-groupsleave--выход-из-группы) предупреждать владельца, что владелец будет назначен автоматически, а единственного участника — что переписка станет недоступна.
5. **События `groups`.** Обработать по [описанию](../websocket/Groups.md):
   - `created` — слить Conversation как `singleCreated`, версия — в курсор синхронизации;
   - `membersAdded` с `changeVersion` (вас добавили) — сохранить GroupInfo, загрузить группу через `/conversations/getBatch` и только после успешного ответа добавить `changeVersion` в курсор; при неудаче хранить `conversationId` в `pendingConversationIds` и повторять `getBatch` после каждого переподключения;
   - `membersRemoved` / `memberLeft` с `removedConversation` (вас удалили или вы вышли) — применить метку по правилам [RemovedConversation](../Objects.md#объект-removedconversation), версию — в курсор, `totalUnreadCount` — как в ReadInfo;
   - остальные случаи — применить GroupInfo; курсор не двигается.
6. **Метки удаления.** Хранить `removedVersions[conversationId]` для каждой применённой метки, в том числе по незагруженным перепискам, и отбрасывать пришедшие версии переписки с `changeVersion` не больше метки. Метки из `removedConversations` при синхронизации `changedAfter` применять так же и учитывать их `changeVersion` при выборе следующей страницы и курсора. Если метод по известной группе ответил `5002` (или `6002` для `getBlock`) — проверить её через `getBatch` и при `notFoundIds` удалить локально.
7. **Статус «прочитано» в группе.** Учитывать только участников из текущей GroupInfo и только сообщения с `messageId > joinedAfterMessageId` участника; при новой GroupInfo убирать из меты прочтения тех, кого в ней нет. Пользователей из `memberRead` и `getMembersReadMeta` загружать по `userIds` / action `users`.
