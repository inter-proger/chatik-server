## POST /conversations/createSingle — Создание личной переписки

Создаёт личную переписку (`type: "single"`) между текущим пользователем и указанным. Если такая переписка уже существует — возвращает её без ошибки. Требует активной сессии.

### Параметры запроса

| Поле     | Тип | Обязательное | Описание                                          |
|----------|-----|--------------|---------------------------------------------------|
| `userId` | Int | Да           | Идентификатор пользователя, с которым создаётся переписка |

### Успешный ответ

| Поле           | Тип          | Описание                                                        |
|----------------|--------------|-----------------------------------------------------------------|
| `conversation` | Conversation | Объект [Conversation](../Objects.md#объект-conversation) созданной или уже существующей переписки |

```json
{
  "status": 1,
  "response": {
    "conversation": {
      "conversationId": 1,
      "type": "single",
      "memberIds": [1, 2],
      "name": null,
      "avatar": null,
      "opponentUserId": 2,
      "lastMessage": null,
      "positionUpdatedAt": 1790846400123,
      "updatedInfoAt": 1790846400123,
      "unreadCount": 0,
      "lastReadMessageId": 0,
      "changeVersion": 1
    }
  },
  "actions": [
    { "type": "users", "data": { "userIds": [1, 2] } }
  ]
}
```

Также отдаётся [action `users`](../General.md#action-users) с участниками переписки.

Новая переписка сразу появляется в списке у всех участников — наверху, с `lastMessage: null` и `positionUpdatedAt`, равным времени создания. Если переписка создана (а не найдена существующая), участникам рассылается WebSocket-событие [`conversations` / `singleCreated`](../websocket/Conversations.md#conversations--singlecreated--создана-личная-переписка).

### Ошибки

| Код  | Описание                                       |
|------|------------------------------------------------|
| 2003 | Пользователь не авторизован                    |
| 4001 | Пользователь не найден / невалидный `userId`   |
| 5001 | `userId` совпадает с текущим пользователем     |

## GET /conversations/getList — Список переписок

Возвращает переписки, в которых состоит текущий пользователь, — сначала поднятые последними: по убыванию `positionUpdatedAt`, при равенстве — по убыванию `conversationId`. Переписка поднимается наверх при новом сообщении; правка сообщения её не поднимает. Требует активной сессии.

Для получения следующей страницы увеличьте `offset` на количество уже полученных переписок; запрашивать дальше имеет смысл, пока `hasNext` равен `true`. Если во время листания переписка поднялась, на следующей странице может повториться уже полученная — клиент дедуплицирует по `conversationId` и сливает версии по [правилам слияния](../WebSocket.md#слияние-переписки).

Фильтры `positionUpdatedAfter` и `changedAfter` нужны для [синхронизации списка](#синхронизация-списка) после переподключения.

### Параметры запроса

| Поле                   | Тип | Обязательное | Описание |
|------------------------|-----|--------------|----------|
| `offset`               | Int | Нет          | Сколько первых переписок пропустить; по умолчанию 0. Не используется вместе с `changedAfter` |
| `count`                | Int | Нет          | Максимальное количество переписок в выдаче; по умолчанию 30, максимум 100 (большие значения урезаются до 100) |
| `positionUpdatedAfter` | Int | Нет          | Только переписки с `positionUpdatedAt` строго больше значения (мс). Сортировка и пагинация — как без фильтра |
| `changedAfter`         | Int | Нет          | Только переписки с `changeVersion` строго больше значения — изменившиеся (информация или прочтение, в том числе на другом устройстве) после этой [версии пользователя](../Objects.md#версия-пользователя). Сортировка — по **возрастанию** `changeVersion`; следующая страница — `changedAfter` = `changeVersion` последней полученной переписки, без `offset` |

`hasNext` считается в пределах фильтра.

### Успешный ответ

| Поле               | Тип            | Описание                                                        |
|--------------------|----------------|-----------------------------------------------------------------|
| `conversations`    | Conversation[] | Список объектов [Conversation](../Objects.md#объект-conversation)            |
| `hasNext`          | Bool           | Есть ли ещё переписки после этой страницы                       |
| `totalUnreadCount` | Int            | Непрочитанные текущим пользователем по всем перепискам          |
| `changeVersion`    | Int            | Текущая [версия пользователя](../Objects.md#версия-пользователя); `totalUnreadCount` и список сняты на ней |

```json
{
  "status": 1,
  "response": {
    "conversations": [
      {
        "conversationId": 1,
        "type": "single",
        "memberIds": [1, 2],
        "name": null,
        "avatar": null,
        "opponentUserId": 2,
        "lastMessage": {
          "messageId": 15,
          "type": "text",
          "text": "Привет!",
          "updatedAt": 1790846400123
        },
        "positionUpdatedAt": 1790846400123,
        "updatedInfoAt": 1790846000456,
        "unreadCount": 1,
        "lastReadMessageId": 14,
        "changeVersion": 118
      }
    ],
    "hasNext": false,
    "totalUnreadCount": 3,
    "changeVersion": 120
  },
  "actions": [
    { "type": "users", "data": { "userIds": [1, 2] } }
  ]
}
```

Также отдаётся [action `users`](../General.md#action-users) с участниками всех переписок в выдаче (не отдаётся, если список пуст).

`totalUnreadCount` клиент применяет по правилам [ReadInfo](../Objects.md#объект-readinfo) — с версией `changeVersion` ответа.

### Синхронизация списка

После каждого (пере)подключения WebSocket клиент выполняет два независимых запроса: поднявшиеся переписки приходят через `positionUpdatedAfter`, остальные изменения (информация и прочтение) — через `changedAfter`.

**Поднявшиеся переписки (`positionUpdatedAfter`).** Клиент хранит `maxPositionUpdatedAt` — максимальный `positionUpdatedAt` из полученных переписок (из ответов и событий). Значение фильтра клиент передаёт **с запасом** — минус несколько секунд (например, 5): время сообщения фиксируется до коммита транзакции, и переписка с чуть меньшим временем может стать видна чуть позже. Лишние переписки в ответе безвредны — слияние идемпотентно.

1. Запрос с `positionUpdatedAfter = maxPositionUpdatedAt` (минус запас) и `offset = 0`.
2. `hasNext: false` → все поднявшиеся переписки получены: клиент сливает их по [правилам](../WebSocket.md#слияние-переписки), вставляет новые и пересортировывает список. Остальной список остаётся валидным.
3. `hasNext: true` → поднялось больше страницы. Клиент оставляет только полученную страницу, остальные переписки удаляет из списка и дальше подгружает обычной пагинацией без фильтра, начиная с `offset` = размеру полученной страницы (при одинаковой сортировке страница с фильтром совпадает с началом полного списка).

**Остальные изменения (`changedAfter`).** Клиент хранит курсор `syncedChangeVersion` — версию, до которой он видел все изменения (см. [курсор синхронизации](../WebSocket.md#курсор-синхронизации)). Запас не нужен: версия — счётчик под блокировкой, версия N+1 не становится видна раньше версии N. При первой загрузке списка (по `offset`) курсор — `changeVersion` верхнего уровня **первой** страницы: изменения во время листания получат версию больше, и их догонит синхронизация.

1. Запрос с `changedAfter = syncedChangeVersion`.
2. Пока `hasNext: true` — следующая страница: `changedAfter` = `changeVersion` последней полученной переписки. Переписка, изменившаяся во время листания, уходит в конец выдачи и придёт позже — ничего не пропускается.
3. После последней страницы `syncedChangeVersion` = максимум из `changeVersion` ответа и полученных переписок; дальше курсор двигается по [правилу непрерывности](../WebSocket.md#курсор-синхронизации).

Полученные переписки сливаются только с **уже загруженными** на клиенте — по всем правилам слияния, включая позицию (если переписка за это время поднялась, она перемещается). Новые в список не добавляются: иначе переписка с условной 1000-й позиции появилась бы в списке, где прогружено 200. Изменения прочтения в незагруженных переписках учтены в `totalUnreadCount` ответа.

### Ошибки

| Код  | Описание                                                                      |
|------|-------------------------------------------------------------------------------|
| 1004 | `offset`, `count`, `positionUpdatedAfter` или `changedAfter` не являются целым неотрицательным числом (`count` должен быть больше 0); `changedAfter` передан вместе с `positionUpdatedAfter` или `offset` |
| 2003 | Пользователь не авторизован                                                   |

## POST /conversations/markRead — Отметка прочтения

Отмечает прочитанными сообщения переписки до `messageId` включительно (см. [прочтение](../Objects.md#прочтение)). Идемпотентен: повтор или более старый `messageId` возвращает текущий ReadInfo без изменений. Требует активной сессии; пользователь должен состоять в переписке.

Клиент вызывает метод с id последнего видимого сообщения, с debounce при прокрутке, и не вызывает, если id не больше локального `lastReadMessageId`. Локальный сдвиг указателя — оптимистичный; ответ или событие подтверждают его по версии.

### Параметры запроса

| Поле             | Тип | Обязательное | Описание |
|------------------|-----|--------------|----------|
| `conversationId` | Int | Да           | Идентификатор переписки |
| `messageId`      | Int | Да           | Последнее прочитанное сообщение — из этой переписки |

### Успешный ответ

| Поле       | Тип      | Описание |
|------------|----------|----------|
| `readInfo` | ReadInfo | Состояние прочтения переписки и общий счётчик — объект [ReadInfo](../Objects.md#объект-readinfo) |

```json
{
  "status": 1,
  "response": {
    "readInfo": {
      "conversationId": 1,
      "lastReadMessageId": 15,
      "unreadCount": 0,
      "totalUnreadCount": 3,
      "changeVersion": 118
    }
  }
}
```

Если прочтение что-то изменило, во все соединения текущего пользователя (включая соединение устройства, с которого прочитали) рассылается WebSocket-событие [`conversations` / `read`](../websocket/Conversations.md#conversations--read--переписка-прочитана), а остальным участникам — [`conversations` / `memberRead`](../websocket/Conversations.md#conversations--memberread--участник-прочитал-переписку).

### Ошибки

| Код  | Описание |
|------|----------|
| 2003 | Пользователь не авторизован |
| 5002 | Переписка не найдена, невалидный `conversationId` или пользователь в ней не состоит |
| 6001 | Сообщение не найдено, невалидный `messageId` или сообщение из другой переписки |

## GET /conversations/getMembersReadMeta — Прочтение другими участниками

Возвращает указатели прочтения всех участников переписки, кроме текущего пользователя, — для статуса «прочитано» у сообщений (см. [MemberReadMeta](../Objects.md#объект-memberreadmeta)). Требует активной сессии; пользователь должен состоять в переписке.

### Параметры запроса

| Поле             | Тип | Обязательное | Описание |
|------------------|-----|--------------|----------|
| `conversationId` | Int | Да           | Идентификатор переписки |

### Успешный ответ

| Поле              | Тип              | Описание |
|-------------------|------------------|----------|
| `membersReadMeta` | MemberReadMeta[] | Указатели остальных участников — объекты [MemberReadMeta](../Objects.md#объект-memberreadmeta), по возрастанию `userId` |

```json
{
  "status": 1,
  "response": {
    "membersReadMeta": [
      { "userId": 2, "lastReadMessageId": 15 }
    ]
  }
}
```

Текущего пользователя в ответе нет: его указатель — `lastReadMessageId` в [Conversation](../Objects.md#объект-conversation) и [ReadInfo](../Objects.md#объект-readinfo), он сливается по `changeVersion`. Action `users` метод не отдаёт: все `userId` — участники переписки, клиент уже знает их из её `memberIds`.

### Правила клиента

- **Когда запрашивать.** При открытии экрана переписки (сначала показать сохранённую мету, если есть) и после каждого переподключения WebSocket (`auth` / `connected`), пока экран открыт: события за время разрыва потеряны. Мета хранится локально и показывается в оффлайне.
- **Слияние.** Для каждого участника берётся максимум из локального значения, ответа и событий — порядок их прихода для указателей не важен. Состав участников берётся из ответа: участников, которых в ответе нет, клиент удаляет из локальной меты.
- **События.** [`conversations` / `memberRead`](../websocket/Conversations.md#conversations--memberread--участник-прочитал-переписку) применяется, если переписка открыта или её мета уже сохранена; мету для других переписок событие не создаёт. Событие от участника, которого нет в мете, добавляет его.
- **Новое сообщение.** Отправка сдвигает указатель отправителя на своё сообщение, отдельного `memberRead` при этом нет. Получив [`messages` / `received`](../websocket/Messages.md#messages--received--новое-сообщение) от участника X (при том же условии, что и для `memberRead`), клиент ставит указатель X = `max(указатель X, message.messageId)`. Следствие: если X ответил, не открывая переписку (например, из уведомления), все сообщения до его ответа показываются прочитанными им.

### Ошибки

| Код  | Описание |
|------|----------|
| 2003 | Пользователь не авторизован |
| 5002 | Переписка не найдена, невалидный `conversationId` или пользователь в ней не состоит |

## GET /conversations/getBatch — Переписки по списку id

Возвращает переписки по идентификаторам. Нужен, когда клиент узнал о переписке, которой нет в его загруженном списке: например, пришло событие [`messages` / `received`](../websocket/Messages.md#messages--received--новое-сообщение) по чату, ещё не прогруженному пагинацией. Требует активной сессии.

### Параметры запроса

| Поле              | Тип   | Обязательное | Описание |
|-------------------|-------|--------------|----------|
| `conversationIds` | Int[] | Да           | Идентификаторы переписок, от 1 до 100 штук. Через запятую (`conversationIds=1,2,3`) или массивом (`conversationIds[]=1&conversationIds[]=2`). Повторы игнорируются |

### Успешный ответ

| Поле            | Тип            | Описание |
|-----------------|----------------|----------|
| `conversations` | Conversation[] | Найденные объекты [Conversation](../Objects.md#объект-conversation) — в порядке `conversationIds` (не в порядке списка чатов: место в списке клиент определяет по `positionUpdatedAt`) |
| `notFoundIds`   | Int[]          | Идентификаторы, для которых переписка не найдена **или текущий пользователь в ней не состоит**, — в порядке `conversationIds`. Чужие переписки неотличимы от несуществующих |

```json
{
  "status": 1,
  "response": {
    "conversations": [
      {
        "conversationId": 7,
        "type": "single",
        "memberIds": [1, 5],
        "name": null,
        "avatar": null,
        "opponentUserId": 5,
        "lastMessage": { "messageId": 42, "type": "text", "text": "Привет!", "updatedAt": 1790846400123 },
        "positionUpdatedAt": 1790846400123,
        "updatedInfoAt": 1790846000456,
        "unreadCount": 0,
        "lastReadMessageId": 42,
        "changeVersion": 118
      }
    ],
    "notFoundIds": [999]
  },
  "actions": [
    { "type": "users", "data": { "userIds": [1, 5] } }
  ]
}
```

Также отдаётся [action `users`](../General.md#action-users) с участниками всех переписок в выдаче (не отдаётся, если список пуст).

### Ошибки

| Код  | Описание |
|------|----------|
| 1004 | `conversationIds` не передан, пуст, содержит больше 100 элементов или элемент, не являющийся целым неотрицательным числом |
| 2003 | Пользователь не авторизован |
