# /conversations — Переписки

[← Методы API](../Methods.md) · [Документация API](../../../API_Documentation.md)

## POST /conversations/createSingle — Создание личной переписки

Создаёт личную переписку (`type: "single"`) между текущим пользователем и указанным. Если такая переписка уже существует — возвращает её без ошибки. Требует активной сессии.

### Параметры запроса

| Поле     | Тип | Обязательное | Описание                                          |
|----------|-----|--------------|---------------------------------------------------|
| `userId` | Int | Да           | Идентификатор пользователя, с которым создаётся переписка |

### Успешный ответ

| Поле           | Тип          | Описание                                                        |
|----------------|--------------|-----------------------------------------------------------------|
| `conversation` | Conversation | Объект [Conversation](../Objects.md#объект-conversation) созданной или уже существующей переписки |

```json
{
  "status": 1,
  "response": {
    "conversation": {
      "conversationId": 1,
      "type": "single",
      "memberIds": [1, 2],
      "name": null,
      "avatar": null,
      "opponentUserId": 2,
      "lastMessage": null,
      "positionUpdatedAt": 1790846400123,
      "updatedInfoAt": 1790846400123
    }
  },
  "actions": [
    { "type": "users", "data": { "userIds": [1, 2] } }
  ]
}
```

Также отдаётся [action `users`](../General.md#action-users) с участниками переписки.

Новая переписка сразу появляется в списке у всех участников — наверху, с `lastMessage: null` и `positionUpdatedAt`, равным времени создания. Если переписка создана (а не найдена существующая), участникам рассылается WebSocket-событие [`conversations` / `singleCreated`](../websocket/Conversations.md#conversations--singlecreated--создана-личная-переписка).

### Ошибки

| Код  | Описание                                       |
|------|------------------------------------------------|
| 2003 | Пользователь не авторизован                    |
| 4001 | Пользователь не найден / невалидный `userId`   |
| 5001 | `userId` совпадает с текущим пользователем     |

## GET /conversations/getList — Список переписок

Возвращает переписки, в которых состоит текущий пользователь, — сначала поднятые последними: по убыванию `positionUpdatedAt`, при равенстве — по убыванию `conversationId`. Переписка поднимается наверх при новом сообщении; правка сообщения её не поднимает. Требует активной сессии.

Для получения следующей страницы увеличьте `offset` на количество уже полученных переписок; запрашивать дальше имеет смысл, пока `hasNext` равен `true`. Если во время листания переписка поднялась, на следующей странице может повториться уже полученная — клиент дедуплицирует по `conversationId` и сливает версии по [правилам слияния](../WebSocket.md#слияние-переписки).

Фильтры `positionUpdatedAfter` и `updatedInfoAfter` нужны для [синхронизации списка](#синхронизация-списка) после переподключения.

### Параметры запроса

| Поле                   | Тип | Обязательное | Описание |
|------------------------|-----|--------------|----------|
| `offset`               | Int | Нет          | Сколько первых переписок пропустить; по умолчанию 0. Не используется вместе с `updatedInfoAfter` |
| `count`                | Int | Нет          | Максимальное количество переписок в выдаче; по умолчанию 30, максимум 100 (большие значения урезаются до 100) |
| `positionUpdatedAfter` | Int | Нет          | Только переписки с `positionUpdatedAt` строго больше значения (мс). Сортировка и пагинация — как без фильтра |
| `updatedInfoAfter`     | Int | Нет          | Только переписки с `updatedInfoAt` строго больше значения (мс), а если передан `updatedInfoAfterId` — у которых пара `(updatedInfoAt, conversationId)` строго больше `(updatedInfoAfter, updatedInfoAfterId)`. Сортировка — по **возрастанию** `updatedInfoAt`, затем `conversationId`; следующая страница — курсором, без `offset` |
| `updatedInfoAfterId`   | Int | Нет          | Курсор следующей страницы для `updatedInfoAfter`: `conversationId` последней полученной переписки. Только вместе с `updatedInfoAfter` |

`hasNext` считается в пределах фильтра.

### Успешный ответ

| Поле            | Тип            | Описание                                                        |
|-----------------|----------------|-----------------------------------------------------------------|
| `conversations` | Conversation[] | Список объектов [Conversation](../Objects.md#объект-conversation)            |
| `hasNext`       | Bool           | Есть ли ещё переписки после этой страницы                       |

```json
{
  "status": 1,
  "response": {
    "conversations": [
      {
        "conversationId": 1,
        "type": "single",
        "memberIds": [1, 2],
        "name": null,
        "avatar": null,
        "opponentUserId": 2,
        "lastMessage": {
          "messageId": 15,
          "type": "text",
          "text": "Привет!",
          "updatedAt": 1790846400123
        },
        "positionUpdatedAt": 1790846400123,
        "updatedInfoAt": 1790846000456
      }
    ],
    "hasNext": false
  },
  "actions": [
    { "type": "users", "data": { "userIds": [1, 2] } }
  ]
}
```

Также отдаётся [action `users`](../General.md#action-users) с участниками всех переписок в выдаче (не отдаётся, если список пуст).

### Синхронизация списка

После каждого (пере)подключения WebSocket клиент выполняет два независимых запроса: поднявшиеся переписки приходят через `positionUpdatedAfter`, правки без перемещения — через `updatedInfoAfter`. Значения фильтров клиент берёт из данных сервера (часы устройства не используются) и передаёт **с запасом** — минус несколько секунд (например, 5): время сообщения фиксируется до коммита транзакции, и переписка с чуть меньшим временем может стать видна чуть позже. Лишние переписки в ответе безвредны — слияние идемпотентно.

**Поднявшиеся переписки (`positionUpdatedAfter`).** Клиент хранит `maxPositionUpdatedAt` — максимальный `positionUpdatedAt` из полученных переписок (из ответов и событий).

1. Запрос с `positionUpdatedAfter = maxPositionUpdatedAt` (минус запас) и `offset = 0`.
2. `hasNext: false` → все поднявшиеся переписки получены: клиент сливает их по [правилам](../WebSocket.md#слияние-переписки), вставляет новые и пересортировывает список. Остальной список остаётся валидным.
3. `hasNext: true` → поднялось больше страницы. Клиент оставляет только полученную страницу, остальные переписки удаляет из списка и дальше подгружает обычной пагинацией без фильтра, начиная с `offset` = размеру полученной страницы (при одинаковой сортировке страница с фильтром совпадает с началом полного списка).

**Изменения без перемещения (`updatedInfoAfter`).** Клиент хранит `maxUpdatedInfoAt` — максимальный `updatedInfoAt` из полных объектов Conversation (ответы REST, `singleCreated`).

1. Первый запрос — `updatedInfoAfter = maxUpdatedInfoAt` (минус запас), без `updatedInfoAfterId`.
2. Пока `hasNext: true` — следующий запрос с курсором последней полученной переписки: `updatedInfoAfter` = её `updatedInfoAt`, `updatedInfoAfterId` = её `conversationId`. Переписка, изменившаяся во время листания, уходит в конец выдачи и придёт позже — ничего не пропускается.
3. После последней страницы `maxUpdatedInfoAt` = максимум из полученного.

Полученные переписки сливаются только с **уже загруженными** на клиенте — по всем правилам слияния, включая позицию (если переписка за это время поднялась, она перемещается). Новые в список не добавляются: иначе переписка с условной 1000-й позиции появилась бы в списке, где прогружено 200.

### Ошибки

| Код  | Описание                                                                      |
|------|-------------------------------------------------------------------------------|
| 1004 | `offset`, `count`, `positionUpdatedAfter`, `updatedInfoAfter` или `updatedInfoAfterId` не являются целым неотрицательным числом (`count` должен быть больше 0); переданы одновременно `positionUpdatedAfter` и `updatedInfoAfter`; `updatedInfoAfter` передан вместе с `offset`; `updatedInfoAfterId` передан без `updatedInfoAfter` |
| 2003 | Пользователь не авторизован                                                   |

## GET /conversations/getBatch — Переписки по списку id

Возвращает переписки по идентификаторам. Нужен, когда клиент узнал о переписке, которой нет в его загруженном списке: например, пришло событие [`messages` / `received`](../websocket/Messages.md#messages--received--новое-сообщение) по чату, ещё не прогруженному пагинацией. Требует активной сессии.

### Параметры запроса

| Поле              | Тип   | Обязательное | Описание |
|-------------------|-------|--------------|----------|
| `conversationIds` | Int[] | Да           | Идентификаторы переписок, от 1 до 100 штук. Через запятую (`conversationIds=1,2,3`) или массивом (`conversationIds[]=1&conversationIds[]=2`). Повторы игнорируются |

### Успешный ответ

| Поле            | Тип            | Описание |
|-----------------|----------------|----------|
| `conversations` | Conversation[] | Найденные объекты [Conversation](../Objects.md#объект-conversation) — в порядке `conversationIds` (не в порядке списка чатов: место в списке клиент определяет по `positionUpdatedAt`) |
| `notFoundIds`   | Int[]          | Идентификаторы, для которых переписка не найдена **или текущий пользователь в ней не состоит**, — в порядке `conversationIds`. Чужие переписки неотличимы от несуществующих |

```json
{
  "status": 1,
  "response": {
    "conversations": [
      {
        "conversationId": 7,
        "type": "single",
        "memberIds": [1, 5],
        "name": null,
        "avatar": null,
        "opponentUserId": 5,
        "lastMessage": { "messageId": 42, "type": "text", "text": "Привет!", "updatedAt": 1790846400123 },
        "positionUpdatedAt": 1790846400123,
        "updatedInfoAt": 1790846000456
      }
    ],
    "notFoundIds": [999]
  },
  "actions": [
    { "type": "users", "data": { "userIds": [1, 5] } }
  ]
}
```

Также отдаётся [action `users`](../General.md#action-users) с участниками всех переписок в выдаче (не отдаётся, если список пуст).

### Ошибки

| Код  | Описание |
|------|----------|
| 1004 | `conversationIds` не передан, пуст, содержит больше 100 элементов или элемент, не являющийся целым неотрицательным числом |
| 2003 | Пользователь не авторизован |
