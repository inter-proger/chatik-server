# /messages — Сообщения

[← Методы API](../Methods.md) · [Документация API](../README.md)

## GET /messages/getList — Сообщения переписки

Возвращает сообщения переписки целыми [блоками](../Objects.md#блоки-сообщений) — от самых новых к старым: блоки добавляются в выдачу, пока в них не наберётся хотя бы 40 мест (или пока блоки не кончатся). Место занимает и удалённое сообщение, поэтому сообщений в ответе может быть как больше 40, так и меньше — вплоть до 0 при `hasNext: true`, если блоки страницы опустели. Требует активной сессии; пользователь должен состоять в переписке.

Сообщения в `messages` отсортированы от новых к старым (по убыванию `messageId`). Для загрузки более старых сообщений передайте в `blockId` значение `nextBlockId` из предыдущего ответа; запрашивать дальше нужно, пока `hasNext` равен `true`, не опираясь на число сообщений в ответе. `hasNext: true` не гарантирует, что в более старых блоках остались сообщения.

С параметром `receivedAfter` метод служит для догоняющей синхронизации закэшированной переписки — см. [Синхронизация кэша сообщений](#синхронизация-кэша-сообщений).

### Параметры запроса

| Поле             | Тип | Обязательное | Описание                                                                               |
|------------------|-----|--------------|----------------------------------------------------------------------------------------|
| `conversationId` | Int | Да           | Идентификатор переписки                                                                |
| `blockId`        | Int | Нет          | С какого блока начинать (он сам входит в выдачу, дальше идут более старые). Если не указан — с самого нового блока |
| `receivedAfter`  | Int | Нет          | Отметка синхронизации — Unix timestamp в мс. В `messages` попадают только сообщения первой страницы с `createdAt` строго больше отметки, при `hasNext: false` в ответ добавляется `updatedBlockIds`. Не используется вместе с `blockId` |

### Успешный ответ

| Поле          | Тип         | Описание                                                                   |
|---------------|-------------|----------------------------------------------------------------------------|
| `messages`    | Message[]   | Список объектов [Message](../Objects.md#объект-message), от новых к старым. С `receivedAfter` — только сообщения с `createdAt > receivedAfter`; может быть пустым |
| `nextBlockId` | Int \| null | Идентификатор следующего (более старого) блока для загрузки; `null`, если его нет. С `receivedAfter` — только при `hasNext: true`, иначе `null` |
| `hasNext`     | Bool        | Есть ли ещё более старые блоки. С `receivedAfter` — есть ли присланные после отметки сообщения за пределами страницы, то есть нужно ли сбросить кэш |
| `updatedBlockIds` | Int[]   | **Только с `receivedAfter` и при `hasNext: false`.** Блоки переписки, в которых после отметки изменялись или удалялись уже существовавшие сообщения, по убыванию id, не больше 10; может быть пустым. Новые сообщения сами по себе блок сюда не добавляют. Ровно 10 — изменённых блоков может быть больше, клиент сбрасывает кэш |

```json
{
  "status": 1,
  "response": {
    "messages": [
      {
        "messageId": 15,
        "clientId": "6f1c2a9e-4b7d-4e3a-9c51-0d2f8b6a7e14",
        "conversationId": 1,
        "blockId": 2,
        "senderId": 1,
        "type": "text",
        "text": "Привет!",
        "isEdited": false,
        "createdAt": 1790846400123,
        "updatedAt": 1790846400123
      }
    ],
    "nextBlockId": 1,
    "hasNext": true
  },
  "actions": [
    { "type": "users", "data": { "userIds": [1] } }
  ]
}
```

Также отдаётся [action `users`](../General.md#action-users) с отправителями сообщений (не отдаётся, если сообщений нет — в том числе при синхронизации без новых сообщений, даже если `updatedBlockIds` не пуст).

Ответ с `receivedAfter`:

```json
{
  "status": 1,
  "response": {
    "messages": [
      {
        "messageId": 57,
        "clientId": "0b3e6c1a-2f4d-4a8e-9b7c-5d1e2f3a4b6c",
        "conversationId": 1,
        "blockId": 3,
        "senderId": 2,
        "type": "text",
        "text": "Ты где?",
        "isEdited": false,
        "createdAt": 1790850000456,
        "updatedAt": 1790850000456
      }
    ],
    "nextBlockId": null,
    "hasNext": false,
    "updatedBlockIds": [3, 1]
  },
  "actions": [
    { "type": "users", "data": { "userIds": [2] } }
  ]
}
```

### Синхронизация кэша сообщений

Клиент с локальным кэшем переписки узнаёт новые сообщения и изменённые блоки, не перезагружая переписку целиком.

**Отметка синхронизации.** Для каждой закэшированной переписки клиент хранит:

- `syncMark` — максимум `createdAt` и `updatedAt` полученных сообщений этой переписки и `updatedAt` блоков из [`getBlockBatch`](#get-messagesgetblockbatch--сообщения-нескольких-блоков). Часы устройства не используются;
- признак «синхронизирована в текущем соединении». Ставится по завершении синхронизации, если текущее WebSocket-соединение было в состоянии `auth` / `connected` до отправки первого её запроса и осталось текущим до конца. Сбрасывается у всех переписок, когда [текущее соединение](../WebSocket.md#текущее-соединение) закрывается или заменяется; при запуске приложения не стоит ни у одной.

Пока признак стоит, `syncMark` двигается по всему полученному: событиям [`messages` / `received` и `edited`](../websocket/Messages.md), ответам `getList`, `getBlock`, `getBlockBatch`, `send`, `edit`. Пока признака нет, данные сливаются с кэшем как обычно, но **`syncMark` не двигают**: между отметкой и ними может быть дыра из событий, пропущенных без соединения. Отметку из ответов самой синхронизации клиент учитывает при её успешном завершении.

**Когда синхронизировать:** при открытии закэшированной переписки без признака «синхронизирована в текущем соединении» и после переподключения WebSocket — для открытой сейчас переписки. Без кэша переписка грузится как обычно — `getList` без `receivedAfter`.

**Шаги:**

1. Запрос с `receivedAfter = max(syncMark − 5 с, 0)`, без `blockId`. Запас нужен, потому что два сообщения могут получить одну миллисекунду, а события `received` и `edited` — прийти не по порядку. Повторно пришедшие сообщения безвредны — слияние идемпотентно.
2. `hasNext: true` — новых сообщений больше страницы: клиент [сбрасывает кэш](#сброс-кэша-сообщений) относительно этого запроса и продолжает обычную подгрузку по `nextBlockId` (в этом случае страница совпадает с первой страницей без фильтра).
3. `hasNext: false` и в `updatedBlockIds` 10 блоков — клиент [сбрасывает кэш](#сброс-кэша-сообщений) и грузит переписку как без кэша: `getList` без `receivedAfter`, сброс — относительно этого запроса.
4. `hasNext: false` и в `updatedBlockIds` меньше 10 блоков — все новые сообщения в ответе; клиент сливает их с кэшем по [общему правилу](../WebSocket.md#синхронизация), кэш остаётся валидным.
5. Блоки из `updatedBlockIds`, сообщения которых есть в кэше, клиент запрашивает одним [`getBlockBatch`](#get-messagesgetblockbatch--сообщения-нескольких-блоков) и [применяет к кэшу](#применение-блока-к-кэшу). Остальные блоки игнорируются — придут актуальными при обычной подгрузке.
6. Синхронизация завершена после шагов 1–5: `syncMark` = максимум из всего полученного, ставится признак. Если `getBlockBatch` не удался — отметка не двигается, синхронизация повторяется целиком.

#### Сброс кэша сообщений

Сброс — относительно запроса `getList` без `blockId`, ответ которого становится новым началом кэша. Клиент удаляет из кэша переписки все сообщения, кроме полученных событием `received` после отправки этого запроса (они новее любого сообщения ответа) и локальных, ещё не подтверждённых сервером. Ответ сливается с оставшимся по общему правилу.

#### Применение блока к кэшу

Ответ `getBlockBatch` или `getBlock` по блоку — его полное содержимое. Клиент сливает сообщения ответа с кэшем по общему правилу, а сообщения этого блока из кэша, которых в ответе нет, удаляет — кроме полученных событием `received` после отправки запроса. Пустой блок — все его сообщения удалены; подгрузка идёт дальше по `nextBlockId` как обычно.

### Ошибки

| Код  | Описание                                                                            |
|------|-------------------------------------------------------------------------------------|
| 1004 | `receivedAfter` не целое неотрицательное число или передан вместе с `blockId`        |
| 2003 | Пользователь не авторизован                                                         |
| 5002 | Переписка не найдена, невалидный `conversationId` или пользователь в ней не состоит |
| 6002 | Блок не найден, невалидный `blockId` или блок относится к другой переписке           |

## GET /messages/getBlock — Сообщения блока

Возвращает все сообщения одного [блока](../Objects.md#блоки-сообщений) — от новых к старым (по убыванию `messageId`); у пустого блока `messages` пуст. Требует активной сессии; пользователь должен состоять в переписке, к которой относится блок.

### Параметры запроса

| Поле      | Тип | Обязательное | Описание                    |
|-----------|-----|--------------|-----------------------------|
| `blockId` | Int | Да           | Идентификатор блока         |

### Успешный ответ

| Поле       | Тип       | Описание                                                 |
|------------|-----------|----------------------------------------------------------|
| `messages` | Message[] | Список объектов [Message](../Objects.md#объект-message), от новых к старым |

```json
{
  "status": 1,
  "response": {
    "messages": [
      {
        "messageId": 15,
        "clientId": "6f1c2a9e-4b7d-4e3a-9c51-0d2f8b6a7e14",
        "conversationId": 1,
        "blockId": 2,
        "senderId": 1,
        "type": "text",
        "text": "Привет!",
        "isEdited": false,
        "createdAt": 1790846400123,
        "updatedAt": 1790846400123
      }
    ]
  },
  "actions": [
    { "type": "users", "data": { "userIds": [1] } }
  ]
}
```

Также отдаётся [action `users`](../General.md#action-users) с отправителями сообщений блока.

### Ошибки

| Код  | Описание                                                                             |
|------|--------------------------------------------------------------------------------------|
| 2003 | Пользователь не авторизован                                                          |
| 6002 | Блок не найден, невалидный `blockId` или пользователь не состоит в переписке блока    |

## GET /messages/getBlockBatch — Сообщения нескольких блоков

Возвращает [блоки](../Objects.md#объект-messageblock) с сообщениями по идентификаторам. Нужен для обновления изменённых блоков при [синхронизации кэша](#синхронизация-кэша-сообщений). Требует активной сессии.

### Параметры запроса

| Поле       | Тип   | Обязательное | Описание |
|------------|-------|--------------|----------|
| `blockIds` | Int[] | Да           | Идентификаторы блоков, от 1 до 10 штук, могут быть из разных переписок. Через запятую (`blockIds=1,2,3`) или массивом (`blockIds[]=1&blockIds[]=2`). Повторы игнорируются |

### Успешный ответ

| Поле          | Тип            | Описание |
|---------------|----------------|----------|
| `blocks`      | MessageBlock[] | Найденные объекты [MessageBlock](../Objects.md#объект-messageblock) — в порядке `blockIds` |
| `notFoundIds` | Int[]          | Идентификаторы, для которых блок не найден **или текущий пользователь не состоит в его переписке**, — в порядке `blockIds`. Блоки чужих переписок неотличимы от несуществующих |

```json
{
  "status": 1,
  "response": {
    "blocks": [
      {
        "blockId": 3,
        "conversationId": 1,
        "messages": [
          {
            "messageId": 45,
            "clientId": "6f1c2a9e-4b7d-4e3a-9c51-0d2f8b6a7e14",
            "conversationId": 1,
            "blockId": 3,
            "senderId": 1,
            "type": "text",
            "text": "Буду через 10 минут",
            "isEdited": true,
            "createdAt": 1790846400123,
            "updatedAt": 1790849000789
          }
        ],
        "updatedAt": 1790849000789
      },
      {
        "blockId": 1,
        "conversationId": 1,
        "messages": [],
        "updatedAt": 1790849500000
      }
    ],
    "notFoundIds": [999]
  },
  "actions": [
    { "type": "users", "data": { "userIds": [1] } }
  ]
}
```

Также отдаётся [action `users`](../General.md#action-users) с отправителями сообщений всех блоков (не отдаётся, если сообщений нет).

### Ошибки

| Код  | Описание |
|------|----------|
| 1004 | `blockIds` не передан, пуст, содержит больше 10 элементов или элемент, не являющийся целым неотрицательным числом |
| 2003 | Пользователь не авторизован |

## POST /messages/send — Отправка сообщения

Отправляет текстовое сообщение в переписку от лица текущего пользователя. Требует активной сессии; пользователь должен состоять в переписке.

Запрос идемпотентен по `clientId`: если у текущего пользователя уже есть сообщение с таким `clientId` в этой переписке, новое не создаётся — возвращается существующее (как есть, даже если `text` в повторе другой), WebSocket-событие повторно не рассылается. Поэтому при обрыве связи или таймауте клиент повторяет запрос с тем же `clientId`, не рискуя продублировать сообщение.

### Параметры запроса

| Поле             | Тип    | Обязательное | Описание                                                                         |
|------------------|--------|--------------|----------------------------------------------------------------------------------|
| `conversationId` | Int    | Да           | Идентификатор переписки                                                          |
| `text`           | String | Да           | Текст сообщения. Пробелы по краям обрезаются (включая юникодные пробелы и невидимые символы: NBSP, zero-width space/joiner, BOM); после обрезки — от 1 до 4096 символов. Невалидные UTF-8 байты заменяются |
| `clientId`       | String | Да           | Идентификатор сообщения, сгенерированный клиентом до отправки — рекомендуется UUID v4. От 1 до 64 символов `A–Z`, `a–z`, `0–9`, `-`, `_`; регистр учитывается. Должен быть уникален среди сообщений текущего пользователя. Возвращается в `clientId` объекта Message — по нему клиент сопоставляет локальное (ещё не подтверждённое) сообщение с серверным, в т. ч. пришедшим через WebSocket раньше ответа |

### Успешный ответ

| Поле       | Тип      | Описание                                               |
|------------|----------|--------------------------------------------------------|
| `message`  | Message  | Объект [Message](../Objects.md#объект-message) отправленного сообщения |
| `readInfo` | ReadInfo | Состояние прочтения переписки для отправителя — объект [ReadInfo](../Objects.md#объект-readinfo) |

```json
{
  "status": 1,
  "response": {
    "message": {
      "messageId": 15,
      "clientId": "6f1c2a9e-4b7d-4e3a-9c51-0d2f8b6a7e14",
      "conversationId": 1,
      "blockId": 2,
      "senderId": 1,
      "type": "text",
      "text": "Привет!",
      "isEdited": false,
      "createdAt": 1790846400123,
      "updatedAt": 1790846400123
    },
    "readInfo": {
      "conversationId": 1,
      "lastReadMessageId": 15,
      "unreadCount": 0,
      "totalUnreadCount": 3,
      "changeVersion": 118
    }
  },
  "actions": [
    { "type": "users", "data": { "userIds": [1] } }
  ]
}
```

Также отдаётся [action `users`](../General.md#action-users) с отправителем сообщения.

Сообщение становится последним в переписке ([`lastMessage`](../Objects.md#объект-lastmessage)), и переписка поднимается наверх списка: её `positionUpdatedAt` равен `message.createdAt`. Клиент-отправитель поднимает переписку сразу по ответу, не дожидаясь события. Повтор с тем же `clientId` переписку не меняет.

Своё сообщение прочитано: отправка отмечает прочитанной всю переписку до него ([прочтение](../Objects.md#прочтение)). Для новой отправки в `readInfo` `unreadCount = 0`, `lastReadMessageId = message.messageId`; отправитель обновляет счётчики сразу по ответу, по правилам [ReadInfo](../Objects.md#объект-readinfo). При повторе с тем же `clientId` отдаётся текущий ReadInfo переписки: версия не растёт, `lastReadMessageId` может быть больше `message.messageId`, а более поздние чужие сообщения уже учтены в счётчиках.

Участникам переписки рассылается WebSocket-событие [`messages` / `received`](../websocket/Messages.md#messages--received--новое-сообщение).

### Ошибки

| Код  | Описание                                                                            |
|------|-------------------------------------------------------------------------------------|
| 1005 | Текст пустой или длиннее 4096 символов                                              |
| 1006 | Невалидный `clientId`                                                               |
| 2003 | Пользователь не авторизован                                                         |
| 5002 | Переписка не найдена, невалидный `conversationId` или пользователь в ней не состоит |
| 6004 | `clientId` уже использован для сообщения текущего пользователя в другой переписке   |

## POST /messages/edit — Редактирование сообщения

Меняет текст сообщения и помечает его отредактированным (`isEdited: true`, `updatedAt` — время правки). Если новый текст (после обрезки пробелов) совпадает с текущим, сообщение не меняется и возвращается как есть. Требует активной сессии. Редактировать можно только свои сообщения.

### Параметры запроса

| Поле        | Тип    | Обязательное | Описание                                                       |
|-------------|--------|--------------|----------------------------------------------------------------|
| `messageId` | Int    | Да           | Идентификатор сообщения                                        |
| `newText`   | String | Да           | Новый текст; требования те же, что к `text` в `/messages/send` |

### Успешный ответ

| Поле      | Тип     | Описание                                                 |
|-----------|---------|----------------------------------------------------------|
| `message` | Message | Обновлённый объект [Message](../Objects.md#объект-message)            |
| `lastMessage` | LastMessage | Только если отредактировано последнее сообщение переписки: её новый [LastMessage](../Objects.md#объект-lastmessage); иначе поля нет. Позиция переписки не меняется, `updatedInfoAt` переписки становится равным `message.updatedAt` |

```json
{
  "status": 1,
  "response": {
    "message": {
      "messageId": 15,
      "clientId": "6f1c2a9e-4b7d-4e3a-9c51-0d2f8b6a7e14",
      "conversationId": 1,
      "blockId": 2,
      "senderId": 1,
      "type": "text",
      "text": "Привет! Как дела?",
      "isEdited": true,
      "createdAt": 1790846400123,
      "updatedAt": 1790846520456
    },
    "lastMessage": {
      "messageId": 15,
      "senderId": 1,
      "type": "text",
      "text": "Привет! Как дела?",
      "updatedAt": 1790846520456
    }
  },
  "actions": [
    { "type": "users", "data": { "userIds": [1] } }
  ]
}
```

Также отдаётся [action `users`](../General.md#action-users) с отправителем сообщения.

Если текст изменился, участникам переписки рассылается WebSocket-событие [`messages` / `edited`](../websocket/Messages.md#messages--edited--сообщение-отредактировано).

### Ошибки

| Код  | Описание                                                                                     |
|------|----------------------------------------------------------------------------------------------|
| 1005 | Текст пустой или длиннее 4096 символов                                                       |
