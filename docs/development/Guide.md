# Руководство разработчика

[← README](../../README.md)

Как вносить изменения так, чтобы код, документация и тесты оставались согласованными. Устройство кода — [Overview.md](../architecture/Overview.md).

## Локальный запуск

```bash
cp config/db.example.php config/db.php
```

```bash
cp config/app.example.php config/app.php
```

В `config/app.php` задать `WEBSOCKET_INTERNAL_SECRET` (любая строка, кроме пустой). Создать БД `serverai` и применить миграции:

```bash
for f in db/*.sql; do mysql -u root serverai < "$f" || break; done
```

Запустить API и WebSocket-сервер (в двух терминалах):

```bash
php -S localhost:8080 index.php
```

```bash
php websocket/server.php
```

API — `http://localhost:8080`, админка — `http://localhost:8080/admin`. Встроенный сервер с роутером `index.php` пропускает через роутер **все** запросы, поэтому `static/` он не отдаёт: URL загруженных файлов отвечают JSON 404 (сами файлы и записи создаются). Чтобы открывать файлы, нужен nginx перед PHP-FPM — как в [локальном варианте с туннелем](../operations/Deployment.md#локальный-сервер-через-туннель-tuna). Тестовые пользователи для ручной проверки — [TestUsers.md](TestUsers.md).

## Соглашения

- **Без зависимостей.** Ни Composer, ни фреймворков, ни внешних библиотек — только PHP и его расширения. Новое расширение PHP — отразить в [Deployment.md](../operations/Deployment.md#1-требования).
- **Именование.** API (пути, параметры, поля ответов, события) — `lowerCamelCase`; БД (таблицы, колонки, ключи JSON-колонок) — `snake_case`. Преобразование — только в `fromRow()` сущностей.
- **Обработчики — плоские скрипты** по шаблону из [Overview.md](../architecture/Overview.md#жизненный-цикл-запроса). `Response::*` завершают запрос — проверки пишутся подряд.
- **Параметры не доверяются по типу.** `$_POST['x']` может прийти массивом (`x[]=…`) — проверять `is_string()` до `ctype_digit()` и т. п. Строки от клиента — `mb_scrub()` перед записью в БД, длины — по размерам колонок.
- **Чужое неотличимо от несуществующего.** Переписка, где пользователь не участник, чужое сообщение, чужой файл — та же ошибка, что для несуществующего (`5002`, `6001`, `3004`).
- **SQL** — только prepared statements с `?`. В строку подставляются лишь целые числа, уже приведённые через `(int)`, и списки плейсхолдеров (`implode(',', array_fill(0, count($ids), '?'))`).
- **Транзакции и блокировки — в сущностях**, в порядке из [DataModel.md](../architecture/DataModel.md#транзакции-и-блокировки). WS-события — после коммита.
- **Комментарии** — по-русски, объясняют «почему», а не «что». В докблоке метода сущности — формат возвращаемого объекта.
- **Ошибки сервера** не отдаются клиенту — только лог и `9001`. Не ловить исключения, чтобы вернуть «красивую» ошибку, если это не ожидаемый случай (как `1062` для дубликата).

## Чек-листы

Документация, тесты и код меняются **одним коммитом**.

### Новый метод API

1. Файл обработчика `<группа>/<метод>.php` и строка в `$routes` в `index.php`.
2. Новые коды ошибок — константы в `core/ErrorCode.php` (в группе по тысячам).
3. Документация:
   - описание метода — в `docs/api/methods/<Группа>.md` (параметры, ответ, ошибки, пример);
   - ссылка — в оглавлении [Methods.md](../api/Methods.md);
   - коды ошибок — в [Errors.md](../api/Errors.md) (и новые коды, и новый метод у существующих кодов);
   - новые объекты или поля — в [Objects.md](../api/Objects.md);
   - если метод отдаёт actions — в таблицу [General.md](../api/General.md#actions).
4. Тесты — `tests/api/<Группа>Test.php`: успешный ответ, каждая ошибка, `2003`, события.

### Новое WS-событие

1. Публикация в обработчике или сущности после коммита: `WebSocket::publish()` (одинаковое для всех) или `publishEach()` + `delivery()` (если тело зависит от получателя).
2. Документация: событие — в `docs/api/websocket/<Группа>.md`, оглавление — раздел «События» в [docs/api/WebSocket.md](../api/WebSocket.md#события), источник — таблица [«События и источники»](../architecture/WebSocket.md#события-и-источники).
3. Тест — `tests/api/WsEventsTest.php` или тест группы методов.

### Изменение схемы БД

1. Новый файл `db/NNN_описание.sql` со следующим номером ([правила](../architecture/DataModel.md#миграции)); старые миграции не править.
2. Заполнить новые колонки для существующих строк в той же миграции.
3. Новая таблица — в список `TRUNCATE` в `TestCase::resetDatabase()`.
4. Обновить [DataModel.md](../architecture/DataModel.md).

### Новая настройка

1. Константа в шаблоне `config/*.example.php` (настройка окружения) или в закоммиченном `config/*.php` (лимиты и таймауты).
2. [Configuration.md](../operations/Configuration.md); для настроек окружения — [Deployment.md](../operations/Deployment.md#5-конфигурация).
3. Если нужно значение для тестов — `tests/config/`.

### Большая функция

Сначала — документ в `docs/architecture/` с решением: контракт, модель данных, алгоритмы, граничные случаи, принятые решения и альтернативы, раздел «Реализация» со списком изменений. Примеры — [UnreadMessages.md](../architecture/UnreadMessages.md), [ReadReceipts.md](../architecture/ReadReceipts.md). Клиентский контракт после реализации переносится в `docs/api/` — при расхождении верен `docs/api/`. Новый документ — в таблицу раздела в [Overview.md](../architecture/Overview.md#документы-раздела) и в [README](../../README.md).

## Документация

- Только markdown, файлы — в `docs/` по разделам: `api/` — клиентский контракт, `architecture/` — серверное устройство и решения, `operations/` — развёртывание и настройка, `development/` — разработка и тесты. Вход — [README.md](../../README.md) в корне.
- Ссылки между документами — относительные, с якорем: `Файл.md#якорь`. Якорь — заголовок в нижнем регистре, пробелы → `-`, пунктуация удаляется.
- В `docs/api/` пишется только то, что нужно клиенту; серверные детали и обоснования — в `architecture/`.

## Коммиты

Коммит — одно законченное изменение: код + тесты + документация + миграция. Перед коммитом — `php tests/run.php`.
